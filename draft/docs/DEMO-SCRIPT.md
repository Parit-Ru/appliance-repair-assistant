# สคริปต์สาธิตและคำถามที่คาดว่าจะถูกถาม

ประมาณ 8–10 นาที ใช้เว็บจริง `https://parit-ru.github.io/appliance-repair-assistant/` (ปลุก backend ก่อนสาธิต 2 นาที: เปิด `…onrender.com/health` ค้างไว้ เพราะ Render free หลับ ~15 นาที) และเตรียมแผนสำรองรันในเครื่อง (`backend: npm run start:dev`, `frontend: npm run dev`)

> ข้อมูลที่ยืนยันแล้ว: คำค้นและคะแนนด้านล่างมาจากการรันจริงกับโมเดลเมื่อ 13 ต.ค. (เครื่องของผู้พัฒนา) คะแนนบน Render อาจต่างเล็กน้อยถ้ารุ่นไลบรารีต่าง · ส่วน **ยังไม่เคยดูหน้าจอจริงด้วยตา** ให้ซ้อมก่อน 1 รอบ

## ลำดับสาธิต

| # | ทำอะไร | พูดว่า | ต้องเห็น |
|---|---|---|---|
| 1 | หน้าแรก | ปัญหา 3 ข้อของแชทบอท และหลักการ "ลำดับขั้นตอนมาจากเครื่องสถานะ ไม่ใช่ AI" | ตัวอย่างขั้นตอนไฟฟ้าที่ต้องยืนยัน |
| 2 | **เลือกอาการ** → พิมพ์ `แอร์ไม่เย็น` | ระบบเทียบความหมาย เสนอ ≤ 3 ผัง **ให้ผู้ใช้เลือกเอง** พร้อมคะแนน (คะแนนบอกความใกล้ ไม่ใช่ความน่าจะเป็น) | `improper_airflow_temperature` ~0.98 อยู่บนสุด |
| 3 | พิมพ์ `ตู้เย็นไม่เย็น` | เกณฑ์ 0.55: ต่ำกว่าเกณฑ์ → ไม่เดา แนะนำติดต่อศูนย์บริการ | กล่อง "ไม่พบอาการที่ใกล้เคียง…" (**ได้ ~0.49**) |
| 4 | เมนู **อาการทั้งหมด** | ทางสำรองเมื่อค้นหาใช้ไม่ได้ จัดกลุ่มตามประเภท/รุ่น | รายการ 13 อาการ |
| 5 | เลือก **แอร์ไม่ทำงาน เปิดไม่ติด** → ตอบ "ใช่" 2 ครั้ง | ทุกขั้นแสดงที่มา: ชื่อคู่มือ + เลขหน้า | "ที่มาของขั้นตอนนี้: … หน้า 43" |
| 6 | ถึงขั้นเบรกเกอร์ (ด่านความปลอดภัย) | ปุ่มไปต่อถูกปิดจนกว่าจะติ๊กยืนยันคำเตือน | ปุ่มปิด → ติ๊ก → ไปต่อได้ |
| 7 | **พิสูจน์ว่าด่านอยู่ที่เซิร์ฟเวอร์:** รัน `./backend/scripts/demo-safety-gate.ps1 -BaseUrl https://appliance-repair-assistant.onrender.com` | ยิง API ตรงไม่ผ่านหน้าเว็บ ส่ง `continue` ข้ามคำเตือน → 400 `SAFETY_CONFIRMATION_REQUIRED` แล้วสถานะไม่ขยับ | ทุกขั้นขึ้นผ่าน (⚠️ สร้าง session จริง 1 รายการ) |
| 8 | ไปถึงผลลัพธ์ | ประเภทผลลัพธ์ + รายการอุปกรณ์ที่ควรเตรียม (มีที่มา) + ช่องกรอกผลลัพธ์ | กรอกข้อความ → บันทึก → กรอกซ้ำไม่ได้ |
| 9 | รันเทส (ถ้ามีเวลา) | 205 เทส ครอบคลุมเดินทุกเส้นทางของ 13 ผัง | ผ่านทั้งหมด |

**หลีกเลี่ยงในการสาธิต:** พิมพ์ `พัดลมตั้งพื้นส่ายไม่ได้` (ได้ 0.898 หลุดผ่านเกณฑ์ — เป็นข้อจำกัดที่รู้อยู่ ถ้ากรรมการถามเองให้ตอบตรงๆ ตามหัวข้อ Q&A ข้อ 5)

## คำถามที่คาดว่าจะถูกถาม

| # | คำถาม | คำตอบสั้น | หลักฐาน |
|---|---|---|---|
| 1 | LLM ไม่ตัดสินใจขั้นตอนถัดไปได้อย่างไร | ระบบปัจจุบันไม่มี LLM ในเส้นทางตัดสินใจเลย; ขั้นถัดไปมาจาก `resolveNextNode` ของ engine เพียงจุดเดียวจากตารางผัง · ถ้าเปิดโมดูลเรียบเรียง มันทำงานหลัง engine ตัดสินแล้ว รับ/คืนข้อความเดียว | `traversal-engine.ts`, `LLM-REPHRASE-DESIGN.md` |
| 2 | ข้ามด่านความปลอดภัยได้ไหม (เช่น เรียก API ตรง) | ไม่ได้ ด่านอยู่ใน engine ฝั่งเซิร์ฟเวอร์ ข้ามแล้วได้ 400 และไม่มีการเขียนฐานข้อมูล | ข้อ 7 ของสคริปต์ + smoke test 3/3 |
| 3 | ทำไมคำนวณ cosine ในโค้ด ไม่ใช้ฟังก์ชันเวกเตอร์ของ DB | MySQL รุ่นฟรีที่ใช้ไม่มีฟังก์ชันวัดระยะเวกเตอร์ (ตาม TOR) ข้อมูลมีเพียง 36 ข้อความ เก็บในหน่วยความจำได้ | `symptom-matcher.ts` |
| 4 | เกณฑ์ 0.55 มาจากไหน แม่นแค่ไหน | ตั้งต้นจาก FixStep เลือกด้วยชุดตั้งเกณฑ์ 56 ข้อที่ AI ร่าง **ยังไม่ผ่านชุดรายงานที่ล็อกแล้ว** จึงไม่อ้างความแม่นยำ (บอกตัวเลขหลังทำ `EVALUATION-PLAN.md`) | `EVALUATION-PLAN.md` |
| 5 | ถ้าถามเรื่องที่ไม่มีในระบบ จะเป็นอย่างไร | แยกได้ไม่ครบ: ชุดทดสอบเบื้องต้นปฏิเสธถูก ~53% เพราะแบบจำลองเห็นคำว่า "แอร์" แล้วให้คะแนนสูง แต่ระบบ **ไม่เริ่มผังเอง** ผู้ใช้เลือกเอง และทุกขั้นแสดงที่มา; มีแผนปรับ 4 ทาง | `EVALUATION-PLAN.md` §3–4 |
| 6 | ข้อมูลถูกต้องหรือไม่ ใครตรวจ | จากคู่มือ AR70H หน้า 43–44; ผู้พัฒนาตรวจด้วยมือ (ตาม TOR); เครื่องมือตรวจโครงสร้างอัตโนมัติ (ทางตัน ลิงก์เสีย ด่านความปลอดภัยไม่มีคำเตือน) | `validate-graphs.js` |

| 8 | session หายไปเมื่อไร / เก็บอะไร | เก็บ id, ผัง, โหนดปัจจุบัน, ตัวแปร, ประวัติ; หมดอายุ 24 ชม. นับจากการกระทำล่าสุด; ไม่มีข้อมูลส่วนตัว | `session.store.ts` |
