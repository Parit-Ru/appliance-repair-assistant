# ตารางเทียบ TOR กับระบบ (Traceability Matrix)

เทียบ TOR "ระบบช่วยเหลือและแนะนำการซ่อมเครื่องใช้ไฟฟ้าภายในบ้าน" (ปริตต์ รุ่งเรือง / อ.ดร.ศศิน เทียนดี) ทีละข้อกับระบบ ณ **13 ต.ค. 2569**

| สัญลักษณ์ | ความหมาย |
|---|---|
| ✅ | ทำแล้วและมีหลักฐานที่รันซ้ำได้ |
| 🔶 | ทำบางส่วน หรือทำแล้วแต่ติดเงื่อนไข |
| ❌ | ยังไม่ได้ทำ |
| ❓ | ยังไม่ได้ตรวจ/ไม่มีข้อมูล |

ระบบที่ deploy: backend `https://appliance-repair-assistant.onrender.com` · frontend `https://parit-ru.github.io/appliance-repair-assistant/`

## 3. วัตถุประสงค์ (§2) และผลที่คาดว่าจะได้ (§5)

| ข้อ | รายการ | สถานะ | หมายเหตุ |
|---|---|:---:|---|
| §2.1 | ออกแบบโครงสร้างข้อมูลเครื่องสถานะ + แปลงจากคู่มือ | ✅ (แอร์) | schema v2, 13 ผัง |
| §2.2 | เว็บแอปที่ป้องกันการข้ามขั้นตอน ยืนยันก่อนขั้นเสี่ยง แนะนำอุปกรณ์พร้อมที่มา บันทึกผลลัพธ์ | ✅ | ดูตารางด้านบน · deploy แล้ว |
| §5.1 | ผู้ใช้แก้ปัญหาเบื้องต้นเองเป็นลำดับขั้น ลดเวลา/ค่าใช้จ่าย | ❓ | ยังไม่มีการศึกษาผู้ใช้ จึงยังบอกผลนี้ไม่ได้ |
| §5.2 | ระบบเว็บโต้ตอบหลายรอบตามลำดับขั้นตอนที่กำหนด | ✅ | |
| §5.3 | โครงสร้างข้อมูลเครื่องสถานะ + เครื่องมือตรวจสอบความถูกต้อง นำไปใช้ซ้ำกับคู่มืออื่นได้ | ✅ | `validate-graphs.js` (17 กรณีทดสอบตัวเอง) + แม่แบบ `data/templates/` + `DATA-AUTHORING-GUIDE.md` — **ในโฟลเดอร์ draft ยังไม่ได้ย้ายเข้าโปรเจกต์** |
| §5.4 | ผู้ใช้ทราบอุปกรณ์ล่วงหน้า | ✅ (แอร์) | |
| §5.5 | ข้อมูลผลลัพธ์ที่ผู้ใช้รายงาน ใช้ปรับปรุงผังรอบถัดไป | 🔶 | เก็บได้ (ตาราง `sessions.outcome_text`) แต่ยังไม่มีเครื่องมือดู/สรุป นอกจาก `show-session-history.js` |

## 6. สิ่งที่ผมไม่ได้ตรวจ

- เนื้อหาของ 13 ผังตรงกับคู่มือ AR70H หน้า 43–44 หรือไม่ (TOR ระบุว่าผู้พัฒนาตรวจแล้ว)
- ข้อความ "เครื่องมือสนับสนุนเบื้องต้น ไม่ใช่การทดแทนช่าง" ปรากฏที่หน้าไหนของเว็บ
- พฤติกรรมของเว็บบนเบราว์เซอร์จริงและมือถือ (ตรวจเฉพาะใน jsdom และการตอบของเซิร์ฟเวอร์)
- ผู้ใช้จริงใช้งานแล้วแก้ปัญหาได้หรือไม่
