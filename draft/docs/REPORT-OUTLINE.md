# โครงเอกสารรายงานโครงงาน (01418499) พร้อมแหล่งข้อมูลจากโปรเจกต์

โครงนี้ผูกกับ "กิจกรรมที่ 5: ประเมินผลและจัดทำเอกสารรายงาน" ของ TOR ทุกหัวข้อระบุ **ข้อเท็จจริงที่ใช้ได้เลย** (ตรวจแล้วจากโปรเจกต์) และ **สิ่งที่ห้ามอ้าง** (ยังไม่มีหลักฐาน) ลำดับบทเป็นข้อเสนอ ให้ปรับตามแม่แบบของภาควิชา

## บทที่ 1 บทนำ

| หัวข้อ | ใช้ข้อมูลจาก | หมายเหตุ |
|---|---|---|
| ที่มาและความสำคัญ | TOR §1 | ใช้ 3 ข้อจำกัดของแชทบอท: ข้ามขั้นตอน/สร้างข้อมูลเอง, สูญเสียสถานะ, ขั้นตอนไฟฟ้าต้องแน่นอนตรวจย้อนหลังได้ |
| วัตถุประสงค์ | TOR §2 (2 ข้อ) | |
| ขอบเขต | TOR §3 + `TOR-COMPLIANCE.md` §1 | **ระบุตรงๆ ว่าข้อมูลทดสอบคือแอร์ AR70H 13 ผัง** และ 4 ประเภทเป็นขอบเขตเป้าหมาย (ตามที่ตกลงใน Q1) |
| ผลที่คาดว่าจะได้ | TOR §5 | |
| ข้อจำกัด | `TOR-COMPLIANCE.md` §5–6 | เขียนก่อนกรรมการถาม |

## บทที่ 2 ทฤษฎีและงานที่เกี่ยวข้อง

| หัวข้อ | เนื้อหาที่ต้องหาอ้างอิงเอง |
|---|---|
| เครื่องสถานะเชิงกำหนด (DFM/ออโตมาตาจำกัด) | ตำราทฤษฎีออโตมาตา — **ต้องหาอ้างอิงจริง ไม่ใช่จากเอกสารนี้** |
| LLM + RAG และข้อจำกัด (หลอน ข้ามขั้นตอน) | งานวิจัย/เอกสารผู้ให้บริการ |
| ความคล้ายเชิงความหมาย / cosine similarity / sentence embedding | เอกสารโมเดล `paraphrase-multilingual-MiniLM-L12-v2` (Sentence-Transformers) |
| ระบบวินิจฉัยแบบผังตัดสินใจ / expert system | งานที่เกี่ยวข้อง |

> ผมเขียนรายการหัวข้อให้ แต่ไม่ได้ใส่การอ้างอิงใดๆ เพื่อไม่ให้แต่งเอกสารอ้างอิงขึ้นเอง

## บทที่ 6 สรุปและข้อเสนอแนะ

- สรุปตามวัตถุประสงค์ 2 ข้อ โดยใช้สถานะจริงใน `TOR-COMPLIANCE.md` (ไม่ใส่ ✅ ในข้อที่ยัง 🔶)
- งานในอนาคต: แปลงคู่มือ 4 ประเภท (ใช้แม่แบบ + ตัวตรวจ), RAG ถามตอบเสริม (ที่เลื่อนไว้ — ต้องออกแบบไม่ให้ข้ามด่านความปลอดภัย ดู ROADMAP §F.12), ตัวเลือก B–D ของการปฏิเสธนอกขอบเขต, การศึกษาผู้ใช้, ระบบยืนยันตัวตน
