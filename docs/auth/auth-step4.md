# ระบบบัญชีผู้ใช้ ขั้นที่ 4: หน้าจอ (frontend) — เข้าสู่ระบบ ประวัติของบัญชี และหน้าผู้ดูแลระบบ

> ⚠️ **เอกสารนี้บันทึกตอน backend ยังเป็น NestJS** (ก่อน 21 ต.ค. 2569) — ชื่อ `*.controller.ts`, `*.module.ts`, guard, exception filter, decorator และเลขบรรทัดในนี้อาจไม่มีแล้ว เก็บไว้เป็นประวัติการตัดสินใจ · โค้ดปัจจุบันเป็น Express ดูตารางเทียบใน `docs/STUDY_GUIDE.md` §5.7

สถานะ: เขียนครบ · `tsc` + `eslint` + `vitest` (199 เคส, 22 ชุด) + `npm run build` ผ่าน
**ยังไม่ได้ทดสอบ flow ในเบราว์เซอร์จริง** (ดูหัวข้อ 5.1) ต้องทำตามขั้นตอนทดสอบด้วยมือในหัวข้อ 6 ก่อนเชื่อว่าใช้งานได้

## 1. ภาพรวม

ขั้นนี้ต่อหน้าจอเข้ากับ backend ขั้นที่ 1–3:

| เรื่อง | สิ่งที่ทำ |
|---|---|
| เข้าสู่ระบบ/สมัคร | หน้า `/login` และ `/register` เป็น **ทางเลือกเสริม** ไม่บังคับ |
| Guest | ตรวจอาการและดูประวัติด้วย `X-Client-Id` **เหมือนเดิมทุกอย่าง** |
| ผู้ใช้ที่ล็อกอิน | แนบ `Authorization: Bearer <token>` ทุกคำขอ ไม่ส่ง `X-Client-Id` (backend ไม่ดูอยู่แล้ว) |
| Token เสีย/หมดอายุ | ล้างการล็อกอินและแคช แล้วพาไปหน้าเข้าสู่ระบบพร้อมข้อความ และจำหน้าเดิมไว้กลับมาทำต่อ |
| แคช | key มี identity ของผู้ใช้ + ล้างแคชทั้งหมดตอน login/logout → ผู้ใช้คนละคนไม่เห็นข้อมูลของกัน |
| ผู้ดูแลระบบ | เมนู "ผู้ดูแลระบบ" (เฉพาะ admin) + 2 หน้า: สถิติภาพรวม และความเห็นผู้ใช้ |

**หลักการ:** การซ่อนเมนู/หน้า (`AdminRoute`) เป็น UX เท่านั้น การป้องกันจริงอยู่ที่ backend (`JwtAuthGuard` + `RolesGuard`) ถ้าใครแก้ localStorage ให้ role เป็น admin ก็เห็นหน้าได้ แต่ข้อมูลจะไม่มา (backend ตอบ 403)

## 2. แผนภาพการทำงาน (ข้อความ)

```
เปิดแอป
  │
  ├─ ไม่มี token ใน localStorage ──────────────► status = guest
  │                                               (ทุกอย่างเหมือนก่อนมีระบบบัญชี: ส่ง X-Client-Id)
  │
  └─ มี token ─► status = verifying ─► GET /auth/me
                    │                     ├─ 200 ─► status = user (อัปเดตชื่อ/role จากเซิร์ฟเวอร์)
                    │                     ├─ 401 ─► [ดู "token เสีย" ด้านล่าง]
                    │                     └─ เครือข่ายล่ม ─► ใช้ค่าที่จำไว้ต่อ

เข้าสู่ระบบ / สมัคร
  POST /auth/login | /auth/register (ไม่แนบ token) ─► เก็บ token+ชื่อ+role ใน localStorage
  ─► ล้างแคช React Query ทั้งหมด ─► status = user ─► ไปหน้า ?next= (หรือหน้าแรก/ประวัติ)

ทุกคำขอ (api/http.ts)
  มี token ─► แนบ Authorization: Bearer <token>
  ไม่มี token ─► ไม่แนบ (guest) · หน้าประวัติ/เริ่มตรวจแนบ X-Client-Id เฉพาะ guest

token เสีย (คำขอที่แนบ token ไปได้ 401)
  http.ts ─► setUnauthorizedHandler(usedToken)
  AuthProvider: ถ้า token ที่ใช้ = token ปัจจุบัน (กันคำขอเก่าตอบช้า)
     ─► ล้าง localStorage + ล้างแคช ─► ไป /login?reason=expired&next=<หน้าปัจจุบัน>
  คำขอ guest ที่ได้ 401 (ไม่มี token) ไม่ทำอะไร จึงไม่วนซ้ำ

ออกจากระบบ ─► ล้าง token + ล้างแคช ─► กลับหน้าแรก (เป็น guest ที่ client_id เดิมของเบราว์เซอร์)

หน้า /admin/*
  AdminRoute: verifying ─► "กำลังตรวจสอบสิทธิ์"
              guest     ─► /login?reason=login-required&next=...
              user      ─► หน้า "ไม่มีสิทธิ์เข้าถึงหน้านี้"
              admin     ─► แสดงหน้า ─► (backend ตรวจ token อีกครั้งทุก endpoint)
```

## 3. การตัดสินใจและข้อแลกเปลี่ยน

| เรื่อง | ตัดสินใจ | ข้อแลกเปลี่ยน |
|---|---|---|
| (a) กราฟ | สร้างเองด้วย CSS ไม่เพิ่ม library | ไม่ต้องติดตั้งอะไร ใช้สีเดิมของแอป และอ่านด้วย screen reader ได้ (มีตัวเลขข้างแท่ง/รายการซ่อน) · แลกกับที่ไม่มี tooltip/แกน/ซูม และ 90 วันแท่งจะเล็ก |
| (b) ที่เก็บ token | `localStorage` | รีเฟรชแล้วยังอยู่ในระบบ · แลกกับความเสี่ยง XSS (สคริปต์ที่แทรกเข้ามาอ่าน token ได้) ยอมรับสำหรับ demo localhost · ปลอดภัยกว่าคือ httpOnly cookie ซึ่งต้องแก้ backend |
| (c) หน้า admin | 2 route + แถบลิงก์ | ลิงก์ตรง/ปุ่มย้อนกลับใช้ได้ ตัวกรองอยู่ใน URL แยกหน้ากัน |
| (d) ประวัติ guest เดิม | แสดงข้อความ info ในหน้าประวัติเมื่อล็อกอิน | backend ไม่มี "claim" ผู้ใช้ต้องออกจากระบบเพื่อดูประวัติเก่า ข้อความช่วยกันสับสน |
| (e) token หมดอายุกลางการตรวจ | พาไปล็อกอินพร้อม `?next=` หน้าเดิม | session ของ user เปิดต่อแบบ guest ไม่ได้ (backend ตอบ 404) จึงต้องล็อกอินกลับมา |
| ล้างแคช + identity ใน key | ทำทั้งสองชั้น | กันข้อมูลข้ามผู้ใช้แม้คำขอที่ค้างตอบกลับช้าหลังสลับบัญชี · แลกกับโค้ดเพิ่มเล็กน้อย |
| อ่านค่าเริ่มต้น `guest` | `AuthContext` ค่าเริ่มต้น = guest | เทสต์หน้าเดี่ยวๆ ไม่ต้องห่อ Provider และพฤติกรรมเท่าเดิม |
| ข้อมูลที่เก็บฝั่งหน้าจอ | `{token, id, displayName, role}` ไม่เก็บอีเมล | ลดข้อมูลส่วนตัวใน localStorage |

## 5. สิ่งที่ทดสอบแล้ว

**อัตโนมัติ (ผ่านทั้งหมด):** `npx tsc -b`, `npx eslint .`, `npx vitest run` = 199 เคส, `npm run build`
- แนบ `Authorization` เมื่อล็อกอิน / ไม่แนบเมื่อ guest / ไม่แนบเมื่อ `anonymous`
- **401 ที่แนบ token → เรียกตัวจัดการครั้งเดียว** · 401 ตอน guest, 401 ของ login (รหัสผ่านผิด), 403, 404 → **ไม่เรียก** (ไม่วนซ้ำ ไม่กระทบ guest)
- เก็บ/อ่าน token: ข้อมูลเสีย → ถือว่าไม่ล็อกอิน · localStorage ใช้ไม่ได้ → ไม่ล้ม
- `safeNext` ปฏิเสธ URL เต็ม, `//`, `/\`, `javascript:`, หน้าล็อกอินเอง
- `AdminRoute` ทั้ง 4 สถานะ · เมนูตามสถานะ (guest / user / admin)
- **แคชไม่ข้ามผู้ใช้**: B, guest และ admin บนแคชที่มีข้อมูลของ A ไม่เห็นข้อมูลของ A
- หน้า admin: ค่า `null` → "-" (ไม่ใช่ 0 แต่ 0 จริงยังเป็น 0), คำว่า "เดินค้างแล้วหมดอายุ" (ไม่มี abandoned), หมายเหตุกลุ่ม "ไม่ระบุเจ้าของ", ข้อความ comment ที่มี HTML ถูก escape
- เทสต์เดิมของหน้าจอ (ประวัติ ตรวจอาการ ฯลฯ) ยังผ่านโดยไม่ต้องแก้ → guest ไม่ถูกกระทบในระดับที่เทสต์เห็น

## 5.1 สิ่งที่ยังไม่ได้ทดสอบ (ตรงไปตรงมา)

- **ไม่ได้ทดสอบ flow ในเบราว์เซอร์จริงเลย** เทสต์ทั้งหมดเป็น `renderToString` (ไม่มี DOM จริง ไม่มี effect ทำงาน) จึง **ไม่ได้พิสูจน์**: การพิมพ์/กดปุ่มในฟอร์ม, การ redirect จริง (`navigate`), `AuthProvider` ทำงานจริง (ยืนยัน `/auth/me`, ล้างแคช, ตัวจัดการ 401), การรีเฟรชแล้วยังล็อกอิน, localStorage จริง, หน้าตาและการจัดวาง (มือถือ/จอใหญ่) ทั้งหมดนี้ต้องใช้ขั้นตอนในหัวข้อ 6
- **ไม่ได้ทดสอบกับ backend ตัวใหม่**: ตอนตรวจ พบว่าเซิร์ฟเวอร์บนพอร์ต 3000 เป็นโปรเซสเก่า (ยังไม่มี `/auth`, `/admin`) ต้องรีสตาร์ตก่อนทดสอบ (หัวข้อ 6) ยืนยันได้เพียงว่า CORS ของ backend อนุญาตหัวข้อ `Authorization`
- **ข้อมูลจริงในหน้า admin**: ตาราง feedback ว่างอยู่ (0 แถว) หน้าความเห็นจึงยังไม่เคยแสดงข้อมูลจริง ต้องให้คะแนนจากหน้าประวัติก่อนจึงจะเห็น
- ไม่ได้ทดสอบหลายแท็บ, เบราว์เซอร์อื่นนอกจากที่คุณใช้, หรือ localStorage ที่ถูกปิด

### กรณีที่ 1 — Guest ยังใช้ได้เหมือนเดิม
1. เปิดเว็บโดยไม่ล็อกอิน (ไม่มี `fixstep.auth`) → แถบเมนูเห็น "เข้าสู่ระบบ / สมัครสมาชิก" ไม่มีเมนู "ผู้ดูแลระบบ"
2. เลือกเครื่อง → อาการ → ตรวจจนจบ → ไปหน้า "ประวัติการซ่อม"
3. **ที่ควรเห็น:** ตรวจได้ครบ ประวัติมีรายการที่เพิ่งตรวจ ข้อความบนหน้าประวัติพูดถึง "ผูกกับเบราว์เซอร์เครื่องนี้" พร้อมลิงก์ "เข้าสู่ระบบ" · ใน DevTools → Network คำขอ `/history` มีหัวข้อ `X-Client-Id` และ **ไม่มี** `Authorization`

### กรณีที่ 2 — สมัคร → เข้าสู่ระบบอัตโนมัติ → ประวัติแสดงเฉพาะของฉัน
1. กด "สมัครสมาชิก" ลองกดสมัครโดยไม่กรอก → ต้องมีข้อความเตือนใต้ช่อง; ลองรหัสผ่านสั้นกว่า 8 → ต้องเตือน
2. กรอกชื่อ/อีเมลใหม่/รหัสผ่าน ≥ 8 ตัว แล้วสมัคร
3. **ที่ควรเห็น:** ไปหน้าประวัติเอง · แถบเมนูแสดงชื่อ + "ออกจากระบบ" · มีกล่อง info "ประวัติที่ทำก่อนเข้าสู่ระบบอยู่ที่ไหน" · รายการว่าง (ไม่เห็นประวัติของ guest จากกรณีที่ 1) · Network: `/history` มี `Authorization: Bearer …` และไม่มี `X-Client-Id`
4. ตรวจอาการให้จบ 1 ครั้ง → ประวัติแสดง 1 รายการ
5. สมัครซ้ำด้วยอีเมลเดิม → ต้องได้ข้อความ "อีเมลนี้สมัครไว้แล้ว" พร้อมลิงก์ไปเข้าสู่ระบบ
6. รีเฟรชหน้า (F5) → ยังอยู่ในระบบ (ชื่อยังอยู่)

### กรณีที่ 3 — ออกจากระบบแล้ว guest ในเบราว์เซอร์เดิมต้องไม่เห็นประวัติของผู้ใช้
1. จากกรณีที่ 2 กด "ออกจากระบบ" → กลับหน้าแรก, `fixstep.auth` หายจาก Local Storage
2. ไปหน้าประวัติ
3. **ที่ควรเห็น:** เห็นเฉพาะประวัติของ guest จากกรณีที่ 1 (ไม่มีรายการที่ตรวจตอนล็อกอินในกรณีที่ 2) · ข้อความกลับเป็นแบบ guest

### กรณีที่ 4 — ผู้ใช้ A กับ B บนเบราว์เซอร์เดียวกันไม่เห็นประวัติของกันและกัน (เช็กแคช)
1. สมัคร/เข้าสู่ระบบเป็น A → ตรวจ 1 ครั้งให้จบ → เปิดหน้าประวัติ (เห็น 1 รายการ)
2. **ไม่รีเฟรช** กด "ออกจากระบบ" แล้วสมัคร/เข้าสู่ระบบเป็น B → ไปหน้าประวัติ
3. **ที่ควรเห็น:** รายการว่าง (ไม่มีรายการของ A แม้ครู่เดียว) · ลองกดปุ่มย้อนกลับของเบราว์เซอร์ไปหน้ารายละเอียดของ A (`#/history/<id ของ A>`) → ต้องได้ "ไม่พบรายการนี้ในประวัติ"
4. ออกจากระบบแล้วเข้าสู่ระบบเป็น A ใหม่ → เห็นรายการของ A เหมือนเดิม

### กรณีที่ 5 — token หมดอายุ/เสีย → ไปหน้าเข้าสู่ระบบพร้อมข้อความ, คำขอ guest ไม่กระทบ
1. เข้าสู่ระบบเป็น A แล้วเปิดหน้าอาการที่กำลังตรวจอยู่ (`#/session/<id>`) ค้างไว้
2. ใน DevTools → Application → Local Storage แก้ค่า `token` ใน `fixstep.auth` ให้เป็นข้อความมั่ว (เช่นเติมตัวอักษรท้าย) → กดตอบคำถามต่อ หรือรีเฟรช
3. **ที่ควรเห็น:** ถูกพาไป `#/login?reason=expired&next=%2Fsession%2F...` พร้อมข้อความ "การเข้าสู่ระบบหมดอายุ กรุณาเข้าสู่ระบบอีกครั้ง" · `fixstep.auth` หายไป · แถบเมนูกลับเป็นแบบ guest · **ไม่มีการวน/เด้งซ้ำ** (ดู Network ว่า 401 ครั้งเดียว)
4. เข้าสู่ระบบใหม่ → ถูกพากลับ `#/session/<id>` เดิมและตรวจต่อได้
5. (guest ไม่กระทบ) ออกจากระบบ แล้วลองตรวจอาการใหม่ตามปกติ → ใช้ได้ ไม่มีการเด้งไปหน้าล็อกอิน

### กรณีที่ 6 — ผู้ใช้ธรรมดาเปิด /admin ต้องเห็น "ไม่มีสิทธิ์" และไม่มีเมนู admin
1. เข้าสู่ระบบเป็นผู้ใช้ธรรมดา → แถบเมนู **ไม่มี** "ผู้ดูแลระบบ"
2. พิมพ์ `http://localhost:5173/#/admin/analytics` และ `#/admin/feedback`
3. **ที่ควรเห็น:** หน้า "ไม่มีสิทธิ์เข้าถึงหน้านี้" พร้อมลิงก์กลับ (ไม่ใช่หน้าว่าง ไม่มีข้อมูลสถิติ)
4. ยังไม่ล็อกอินแล้วเปิด `#/admin/analytics` → ถูกพาไปหน้าเข้าสู่ระบบพร้อมข้อความ "หน้านี้ต้องเข้าสู่ระบบ"
5. (พิสูจน์ว่า UX ไม่ใช่การป้องกัน) แก้ `role` ใน `fixstep.auth` เป็น `admin` แล้วรีเฟรช → เห็นหน้า admin ได้ แต่ **ต้องไม่มีข้อมูล** แสดงข้อผิดพลาด "ไม่มีสิทธิ์เข้าถึงส่วนนี้" (backend ตอบ 403) และหลังการยืนยัน `/auth/me` role จะถูกแก้กลับเป็น `user`

### กรณีที่ 7 — Admin เห็นหน้า Feedback และ Analytics ด้วยข้อมูลจริง ค่า null เป็น "-"
1. เข้าสู่ระบบด้วยบัญชี admin ที่ seed ไว้ → เห็นเมนู "ผู้ดูแลระบบ" และป้าย "ผู้ดูแลระบบ" ข้างชื่อ
2. เปิด "ผู้ดูแลระบบ" → "สถิติภาพรวม": เปลี่ยนช่วง 7/30/90 วัน (ข้อความช่วงวันที่ใต้ปุ่มเปลี่ยนตาม)
3. **ที่ควรเห็น:** การ์ดสรุป, ป้าย "เดินค้างแล้วหมดอายุ" (ไม่มีคำว่า abandoned), กราฟรายวัน/ผลการตรวจ/ประเภทเครื่อง/อาการ, หมายเหตุกลุ่ม "ไม่ระบุเจ้าของ" · ถ้ายังไม่มีใครให้คะแนน การ์ด "อัตราความพอใจ" ต้องเป็น **"-"** (ไม่ใช่ 0.0%) และ "ความมั่นใจเฉลี่ย" เป็น "-" ถ้าไม่มีตัวอย่าง
4. ให้คะแนน 👍 หรือ 👎 พร้อมข้อความที่หน้ารายละเอียดประวัติของ session ใดก็ได้ แล้วกลับมาเปิด "ความเห็นผู้ใช้"
5. **ที่ควรเห็น:** รายการความเห็น (คะแนน, ข้อความ, ประเภทเครื่อง, ยี่ห้อ, ชนิดเจ้าของ, วันที่) **ไม่มีอีเมลหรือชื่อผู้เขียน** · ลองตัวกรอง 👍/👎 และช่วงวันที่ · ใส่ช่วงวันที่ย้อนกลับ (ตั้งแต่ใหม่กว่า ถึง) → ต้องได้ข้อความ "ตัวกรองไม่ถูกต้อง"
6. ตัวเลขบางส่วนรวม session ของโปรเจกต์เดิมที่ใช้ฐานข้อมูลเดียวกัน (กลุ่ม "ไม่ระบุเจ้าของ") ตามหมายเหตุบนหน้า

## 8. ข้อจำกัดที่รู้

- **ไม่มี claim** ประวัติที่ทำตอนเป็น guest ไม่ย้ายเข้าบัญชี ต้องออกจากระบบเพื่อดู (มีข้อความบอกในหน้าประวัติ)
- **token ใน localStorage** เสี่ยง XSS (ดูหัวข้อ 3) และไม่ sync ข้ามแท็บ: ออกจากระบบในแท็บหนึ่ง แท็บอื่นจะรู้ตัวเมื่อยิงคำขอครั้งถัดไป (ได้ 401 แล้วเด้งไปล็อกอิน)
- **role ใน token** ถ้ายกผู้ใช้เป็น admin ภายหลัง ต้องออกจากระบบแล้วเข้าใหม่ (เมนู admin ใช้ role ที่เก็บไว้/ที่ `/auth/me` ตอบ ส่วนสิทธิ์จริงอยู่ที่ token) และ token ที่ถอนสิทธิ์ admin แล้วยังใช้ได้จนหมดอายุ (`JWT_EXPIRES_IN`)
- **ไม่มี rate limit** ที่หน้าเข้าสู่ระบบ/สมัคร (ข้อจำกัดของ backend)
- **ไม่มีหน้า "ลืมรหัสผ่าน" / เปลี่ยนรหัสผ่าน / ลบบัญชี**
- **กราฟทำเอง** ไม่มี tooltip/ซูม · รายวัน 90 วันแท่งเล็ก
- **หน้า admin อ่านอย่างเดียว** ไม่มีหน้า sessions และ users (ตามที่ตัดสินใจใน Step 3)
- **ความเห็นของผู้ใช้** (comment) อาจมีข้อมูลส่วนตัวที่ผู้ใช้พิมพ์เอง ระบบไม่กรอง
- **ตัวเลขสถิติรวม session ของโปรเจกต์เก่า** ที่ใช้ฐานข้อมูลเดียวกัน (ดู auth-step3.md)
