# 12 — ข้อจำกัดและงานในอนาคต

> หลักการตอบ: บอกข้อจำกัดก่อนถูกถาม แล้วตามด้วย "ระบบรับมืออย่างไร" และ "จะแก้อย่างไร"

## 1. ข้อจำกัด

### 1.1 ครอบคลุมเฉพาะคู่มือที่มี
- **ง่าย:** ตอบได้เฉพาะ Samsung 21 รุ่น 4 ประเภทเครื่อง อาการที่ไม่มีในคู่มือ ระบบตอบไม่ได้
- **เทคนิค:** 631 ผัง · `device_category` เป็น ENUM 4 ค่า (`backend/migrations/002_graphs.sql:11`) และ validator รับแค่ 4 ค่า (`backend/src/authoring/graph-validator.ts:17`) → เพิ่มประเภทเครื่องใหม่ต้องแก้ schema · ไม่มีผัง → "ไม่พบ ระบบไม่เดาให้" + แนะนำศูนย์บริการ (`frontend/src/components/SymptomSearchResults.tsx:15-17`)

### 1.2 ขึ้นกับคุณภาพ PDF และการเตรียมข้อมูล
- **ง่าย:** ถ้า PDF เป็นภาพสแกน หรือ AI ตอนเตรียม chunk แต่งคำเพิ่ม ผังก็ผิดตาม
- **เทคนิค:**
  - authoring รับเฉพาะ PDF ที่มี text layer (ไม่ทำ OCR · `backend/src/authoring/pdf-text.ts:17-18`)
  - ทาง A ใช้ LLM จัดรูป chunk ซึ่งเคยแต่ง "blown/tripped" (`docs/ops/VERIFY-CHUNKS-AGAINST-PDF.md:100`)
  - ตรวจไม่ได้ 48 ผัง เพราะ PDF ไม่มีข้อความหรือไม่ทราบต้นทาง (`docs/ops/VERIFY-GRAPHS-AGAINST-SOURCE.md:30`)
  - คำแปลไทยและลำดับขั้นยังไม่ผ่านการตรวจโดยคน (`:15`)

### 1.3 Citation อยู่ระดับผัง ไม่ใช่ระดับโหนด ⚠ (กรรมการถามแน่)
ตรวจแล้วพบว่า:

| เรื่อง | ข้อเท็จจริง | หลักฐาน |
|---|---|---|
| โหนดเก็บเลขหน้าของตัวเองไหม | **ไม่** ตาราง `nodes` ไม่มีคอลัมน์หน้า มีแค่ `graphs.source`, `page_start`, `page_end` | `backend/migrations/002_graphs.sql:26-84` |
| แสดงให้ผู้ใช้เห็นไหม | **เห็นทุกขั้น** แต่เป็นหน้าของผัง: "ที่มาของขั้นตอนนี้: คู่มือ … หน้า 37" | `backend/src/traversal-engine/traversal-engine.ts:131-134` · `frontend/src/components/step/ReferenceLine.tsx:15-18` |
| ระดับโหนดมีไหม | มีบางส่วนเป็น**ข้อความในเนื้อโหนด** เช่น "(คู่มือหน้า 15 และ 37)", "(คู่มือหน้า 40)" ผู้พัฒนาเขียนไว้ในข้อความ ไม่ใช่ฟิลด์แยก | ผัง `samsung_ge83mdt_um_not_cooked_at_all` |
| ไม่สอดคล้องกัน | ผังข้างบนแสดง "หน้า 37" ทุกขั้น แต่ข้อความในโหนดอ้างหน้า 3, 8, 9, 10, 15, 40 ด้วย → **หน้าที่แสดงไม่ครอบคลุมทุกขั้น** | `data/manuals/samsung_ge83mdt_um_de68_04111e.json` |
| ผังจาก authoring | LLM ให้ `source_page` รายโหนดและ validator ตรวจแล้ว แต่ตอน publish **ทิ้งค่านี้** เหลือช่วงหน้าของผัง | `backend/src/authoring/draft-manual.ts:26-28, 55-58` |
| ข้อความที่ผู้พัฒนาเขียนเพิ่ม | 1,264 โหนด (27%) มี `author_note` บอกว่าไม่ได้มาจากคู่มือตรงๆ แต่ **ไม่แสดงให้ผู้ใช้เห็น** (GraphRepository ไม่ SELECT คอลัมน์นี้) | `backend/src/traversal/graph.repository.ts:132-139` |
| ไม่มีลิงก์ไป PDF | แสดงเป็นข้อความ ไม่มีลิงก์เปิดหน้า PDF | `ReferenceLine.tsx` |

**วิธีตอบ:** "ทุกขั้นแสดงชื่อคู่มือและหน้าที่ผังนั้นมาจาก และข้อความหลายขั้นระบุหน้าย่อยไว้ในตัว แต่ยอมรับว่ายังไม่ใช่ citation รายโหนดแบบมีโครงสร้าง และส่วนที่ผู้พัฒนาเติมเอง เรามี `author_note` กำกับในข้อมูล แต่ยังไม่ได้แสดงบนหน้าจอ ถ้าแก้ จะเพิ่มคอลัมน์ `source_page` ใน nodes (authoring มีค่านี้อยู่แล้ว แค่ไม่ได้บันทึก) และแสดงป้าย 'ผู้พัฒนาเพิ่มเติม' จาก author_note"

### 1.4 การค้นหาเป็น in-memory brute force — ไม่ scale
- **ง่าย:** เทียบกับทุกข้อความทุกครั้ง เร็วพอที่ ~3,800 ข้อความ แต่ถ้ามีเป็นแสนจะช้า
- **เทคนิค:** O(N·d) ต่อคำค้น, embed ใหม่ทุกครั้งที่บูต, ดัชนีอยู่ใน process เดียว (หลาย instance ไม่ sync), RAM ทั้ง process ~250–310 MB บนเพดาน 512 MB ของ Render free (ไฟล์ 03 §8-9)

### 1.5 ความแม่นยำของการค้นหายังไม่ได้วัด และ threshold มาจากชุดที่ไม่ตรงกับข้อมูลปัจจุบัน
- threshold 0.55 ตั้งจากชุดคำค้นของคู่มือแอร์ที่ AI ร่าง (ไฟล์ 03 §4, ไฟล์ 10)
- ภายในรุ่นเดียวกัน คะแนนสูงกันหมด เกณฑ์แยก "ตรง/ไม่ตรง" ได้ไม่ดี (`docs/STUDY_GUIDE.md:617`)

### 1.6 LLM ยังอาจผิดได้
- rephrase: guard ตรวจตัวเลข รหัส และจำนวน "ไม่" แต่ไม่ได้เข้าใจความหมาย → ปิดเป็นค่าเริ่มต้น และไม่ใช้กับโหนดอันตราย (`backend/src/rephrase/rephrase.service.ts:38-40`)
- authoring: LLM อาจตกหล่นอาการ/คำเตือน → มี validator (W_PAGE_RISK) และคนตรวจ แต่คนตรวจก็พลาดได้
- ทั้งสองส่วนยังไม่ได้ทดสอบกับ Groq จริงหลังย้ายเป็น Express

### 1.7 ระบบไม่ใช่การวินิจฉัยยืนยัน
- **ง่าย:** ระบบพาตรวจตามรายการในคู่มือเพื่อหาสาเหตุที่**เป็นไปได้** และสิ่งที่ผู้ใช้แก้เองได้อย่างปลอดภัย ไม่ได้ยืนยันว่าเครื่องเสียเพราะอะไร
- **เทคนิค:** ผลลัพธ์มีแค่ 4 ชนิด (`user_fixed`, `normal_behavior`, `handoff_informed`, `handoff_unknown` `backend/src/traversal-engine/types.ts:3`) · confidence คือความคล้ายของข้อความ ไม่ใช่ความน่าจะเป็น · ผลขึ้นกับคำตอบของผู้ใช้ ซึ่งอาจตอบไม่ถูก (เช่น "ฟิวส์ขาดไหม")

### 1.8 อื่นๆ
- ไม่มีผู้ใช้จริงทดสอบ (ไฟล์ 10)
- ยืนยันความปลอดภัย = ติ๊ก checkbox ระบบรู้ไม่ได้ว่าทำจริง
- เทสต์อัตโนมัติเหลือ 1 ไฟล์ · เครื่องมือตรวจข้อมูลบางตัวไม่อยู่ใน repo
- ประวัติแสดงได้สูงสุด 50 รายการ (`backend/src/history/history.store.ts:10`)
- guest เปลี่ยนเบราว์เซอร์ = ประวัติเปิดไม่ได้ · ล็อกอินแล้วไม่ย้ายประวัติ guest
- DB ใช้ร่วมกับโปรเจกต์เก่า สถิติจึงปน
- Render free: cold start ~1 นาที, หลับหลัง ~15 นาที (`docs/ops/DEPLOY.md:35`)
- `author_note` บางจุดใช้เครื่องหมายคำพูดเหมือนยกคำของคู่มือ ทั้งที่เป็นการสรุป (13 จุด) และเบอร์โทรใน WT10J7 ที่ PDF เล่มนั้นไม่มี (`VERIFY-GRAPHS-AGAINST-SOURCE.md:36-37`)
