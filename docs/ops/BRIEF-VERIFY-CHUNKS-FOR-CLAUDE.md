# สรุปให้ Claude อ่าน: สคริปต์ตรวจ chunk เทียบ PDF (`scripts/verify_chunks_against_pdf.py`)

> เขียน 15 ต.ค. 2569 · ผู้อ่านคือ Claude อีกหน้าต่าง/อีกเซสชันที่ **ไม่เคยเห็นโปรเจกต์นี้** · ผู้ใช้จะบอกเองว่าต้องการให้ช่วยอะไร ถ้าไม่ชัดให้ถามก่อน
> ตัวเลขทุกตัวด้านล่าง **รันสคริปต์ซ้ำและตรวจกับข้อมูลจริงในวันที่เขียน** (ไม่ได้คัดลอกจากเอกสารเก่า) ส่วนที่ไม่ได้ตรวจเองระบุว่า "ไม่แน่ใจ" ไว้

## 0. สรุป 8 บรรทัด

1. โปรเจกต์: ผู้ช่วยซ่อมเครื่องใช้ไฟฟ้า (วิชา 01418499) ขั้นตอนทั้งหมดต้อง **มาจากคู่มือ Samsung** ระบบเดินขั้นตอนด้วย state machine ที่กำหนดได้ LLM เรียบเรียงถ้อยคำเท่านั้น
2. `data/chuck/*.json` คือ chunk ข้อความ "อาการ / สาเหตุ / วิธีแก้" ที่ได้จากคู่มือ PDF โดย **ให้ LLM จัดรูปแบบ** (ไม่มี parser อัตโนมัติ) จึงเสี่ยงที่ LLM แก้ตัวเลข ตัดขั้นตอน หรือแต่งเนื้อหาเพิ่ม
3. สคริปต์นี้เทียบ chunk 644 อัน (ข้าม Dryer 22) กับข้อความที่ `pdftotext` ดึงจาก PDF ระดับ "คำ" แบบกำหนดได้ ไม่เรียก LLM ไม่แก้ไฟล์ใดๆ
4. ผลรันล่าสุด: **PASS 478 · WARN 49 · FAIL 12 · UNVERIFIABLE 50 · UNMAPPED 24** (+ ภาษาไทย 12/17/2) · chunk_id ซ้ำ 11 · exit code 1
5. สิ่งที่จับได้จริง: เครื่องซักผ้า 3 รุ่น มีช่อง `possible_cause` ที่มีคำซึ่ง **ไม่มีใน PDF เลย** (ดูหัวข้อ 6) → LLM แต่งเพิ่ม
6. **PASS ไม่ได้แปลว่าถูกต้อง 100%** เป็นแค่ "คำและตัวเลขสำคัญอยู่ในหน้าที่อ้าง ตามลำดับ" ความหมายที่เปลี่ยนโดยใช้คำเดิม (เช่น ตัด "ห้าม/not") อาจไม่ถูกจับ
7. **ยังไม่มีมนุษย์ตรวจรับผลนี้** และยังไม่มีใครเปิด PDF ดูด้วยตาเทียบกับ FAIL ทั้ง 12 อัน
8. ห้ามแก้ chunk/PDF ห้ามเรียก LLM ในการตรวจ (ดูหัวข้อ 9)

## 2. รูปแบบ chunk (ตัวอย่างจริง ตัดสั้น)

```json
{
  "chunk_id": "manual_Samsung_WashingMachine_WA5000R_p35_does_not_turn_on",
  "device_category": "Washing Machine", "brand": "Samsung", "model": "WA**R526***/…",
  "source": "Samsung Washing Machine User Manual …",
  "page": 35,
  "content": "Does not turn on. Power supply not matching the product's rating; power cord not completely plugged in; fuse blown or circuit breaker tripped. 1. Make sure you use rated power for the product. 2. … 3. Check the fuse or reset the circuit breaker.",
  "metadata": {
    "symptom": "Does not turn on.",
    "possible_cause": "Power supply not matching the product's rating; … fuse blown or circuit breaker tripped.",
    "solution": "1. Make sure …\n2. …\n3. Check the fuse or reset the circuit breaker.",
    "severity": "medium", "difficulty": "easy",
    "safety_warning": "<ภาษาไทย เขียนโดย LLM ลงท้ายด้วย (คู่มือหน้า N)>"
  }
}
```

- chunk เกือบทั้งหมดเป็นภาษาอังกฤษ ภาษาไทยมีเฉพาะ `DA68-04852N` (ตู้เย็น RS5000FC, 30 อัน) และ `WT10J7` (เครื่องซักผ้า, 7 อัน) ตามที่สคริปต์จำแนกได้
- `content` ควรเท่ากับ `symptom + possible_cause + solution` ต่อกัน ถ้าไม่เท่าสคริปต์ตรวจที่ `content` และแจ้งไว้
- `safety_warning` เป็นข้อความไทยที่ LLM เขียนเอง **ไม่ใช่ข้อความที่คัดลอกจากคู่มือ** จึงตรวจได้แค่เลขหน้ากับตัวเลข/หน่วย

## 4. กฎตัดสินสถานะ (ตามโค้ดจริงใน `evaluate_chunk` 423-545)

เริ่มที่ PASS แล้วไล่ตามลำดับ (แต่ละข้อเลื่อนสถานะขึ้นเป็น WARN/FAIL ได้ ไม่ลดลง):

| เงื่อนไข | สถานะ |
|---|---|
| ไม่มี `page` เป็นตัวเลข / หน้าที่คาดอยู่นอก PDF | FAIL |
| หน้าที่คาดไม่มีข้อความ (< 100 ตัวอักษร) | UNVERIFIABLE (หรือ FAIL ถ้าเนื้อหาไปอยู่หน้าอื่นอย่างชัดเจน) |
| เนื้อหาชัดเจนว่าอยู่หน้าอื่น (เลขหน้าผิด) | FAIL |
| token สำคัญไม่อยู่หน้าที่อ้าง (พบหน้าอื่น หรือไม่พบเลย) | FAIL |
| ตัวเลขกับหน่วยอยู่หน้าเดียวกันแต่ไม่ติดกัน | WARN |
| `cov` < 0.90 | FAIL |
| `cov` < 0.97 หรือ `order` < 0.90 | WARN |
| คำ "ไม่พบใน PDF เลย" ≥ 3 คำ | FAIL |
| คำ "ไม่พบใน PDF เลย" 1–2 คำ | WARN |

ภาษาไทยใช้เกณฑ์อ่อนกว่า (`TH_WARN_THRESHOLD` 0.70 / `TH_PASS_COVERAGE` 0.85 / `TH_PASS_ORDER` 0.70) และติดป้าย `-TH` ถ้าทั้ง PDF ไม่มีหน้าไหนตรงเกิน 0.35 ถือว่า "ดึงข้อความไทยไม่ได้" = UNVERIFIABLE ไม่ใช่ FAIL

**ข้อควรระวังในการอ่านผล:** แถวที่ `cov` = 0.96–0.97 แต่เป็น FAIL ไม่ผิด — FAIL มาจากข้อ "คำไม่พบใน PDF เลย ≥ 3 คำ" ไม่ใช่จาก `cov` (ข้อความเหตุผลในรายงานจะพิมพ์ทั้งสองอย่างไว้ด้วยกัน)

**exit code:** 0 = ไม่มี FAIL และไม่มี chunk_id ซ้ำ · 1 = มี `FAIL` (ไม่นับ `FAIL-TH`) หรือมี id ซ้ำ · 2 = รันไม่ได้ (`main` 878)

## 5. วิธีรัน

ต้องมี `pdftotext` (poppler) บน PATH ในเครื่องผู้ใช้ตรวจเจอที่ `/mingw64/bin/pdftotext` (ผ่าน Git Bash) ส่วน PowerShell ปกติจะมองเห็นหรือไม่ **ไม่แน่ใจ** (`where.exe pdftotext` ตรวจได้)

```powershell
# จากโฟลเดอร์รากของโปรเจกต์ (Python 3.12.10 ในเครื่องผู้ใช้)
python scripts\verify_chunks_against_pdf.py --report $env:TEMP\vr.md
python scripts\verify_chunks_against_pdf.py --only WA5000R --report $env:TEMP\vr.md   # ไฟล์เดียว
python scripts\verify_chunks_against_pdf.py --reverse --report $env:TEMP\vr.md        # + ตรวจย้อนกลับ
```

- รันเต็มชุดใช้ ~71 วินาที ในเครื่องผู้ใช้ (อ่าน PDF 20 ไฟล์ที่ถูกจับคู่)
- ไม่เขียนฐานข้อมูล ไม่เรียกเครือข่าย ไม่แก้ chunk/PDF เขียนแค่ไฟล์รายงาน
- เกณฑ์ทั้งหมดอยู่บรรทัด 40–58 ของสคริปต์ ปรับได้ที่นั่น (`--threshold` ปรับเฉพาะเกณฑ์ FAIL ของภาษาอังกฤษ)

ไมโครเวฟ 6 ไฟล์ offset คงที่ต่อไฟล์ (ตามเอกสารเดิมเป็น PDF สองภาษา ไทยตามด้วยอังกฤษ ซึ่ง offset ที่ใหญ่สอดคล้องกัน แต่ผมไม่ได้เปิด PDF ตรวจโครงหน้าเอง): GE83MDT +40 · MC32K7055 +56 · ME73MD +24 · MG23T5018C +44 · MG28H5125 +42 · MS20A3010A +20 · ส่วนตู้เย็น/ทีวี/เครื่องซักผ้าที่ตรวจได้ = 0 ทุกไฟล์ ไม่มีไฟล์ที่ offset ไม่คงที่ (จึงไม่มีข้อหา "เลขหน้าผิด")

## 7. ข้อจำกัดที่ต้องบอกผู้ใช้/อาจารย์ให้ครบ

1. **PASS ไม่ได้พิสูจน์ความถูกต้อง** เทียบแค่ "คำมีอยู่ในหน้า" ไม่เข้าใจความหมาย ตัด/เติม "ห้าม/not" อาจไม่ถูกจับเพราะคำนั้นมีอยู่ในหน้าอยู่แล้ว
2. ไม่ทำ OCR · ตารางสองคอลัมน์ใน PDF ดึงลำดับสลับได้ (จึงเป็น WARN ไม่ใช่ FAIL)
3. ภาษาไทยเชื่อถือน้อยกว่าอังกฤษ (ป้าย `-TH` แยก ไม่นับใน exit code)
4. **ตรวจไม่ได้ว่า "ตกหล่น"** (chunk ตัดเนื้อหา PDF ออก) `--reverse` เป็นแค่สัญญาณคร่าวๆ
5. token สำคัญใช้กฎประมาณ (regex) อาจพลาดรหัสบางแบบหรือจับคำทั่วไปผิด
6. ตาราง `MAPPING` เขียนมือ จับคู่ผิดไฟล์ = ผลผิดทั้งไฟล์
7. เกณฑ์ 0.97/0.90 ตั้งจากการวัดบน chunk ภาษาอังกฤษ 539 อันของชุดนี้ **ไม่ใช่ค่ามาตรฐาน** ควรทบทวนเมื่อมีคู่มือใหม่

## 9. กติกาของผู้ใช้ที่ใช้กับงานนี้

- **ห้ามแก้ chunk JSON และ PDF** — ถ้าจะแก้ข้อมูล ให้เสนอรายการแก้ แล้วผู้ใช้ยืนยันและแก้เอง
- **ห้ามเรียก LLM** ในกระบวนการตรวจ (LLM คือต้นเหตุของความเสี่ยงที่ตรวจ การตรวจต้องกำหนดได้และย้อนตรวจได้)
- ห้ามแตะฐานข้อมูล (Aiven ใช้ร่วมกับ production และโปรเจกต์เก่า) · ห้ามเปิดไฟล์ `.env` · ห้ามแตะโปรเจกต์เก่า `troubleshoot-assistantv2`
- ผู้ใช้ commit เอง ไม่ต้อง commit/push ให้
- ถ้าไม่แน่ใจ ให้บอกว่า "ไม่แน่ใจ" พร้อมบอกไฟล์:บรรทัดที่ใช้ตัดสิน อย่าเดา · อย่าพูดว่า "ถูกต้อง" หรือ "ตรวจแล้ว" ถ้าไม่ได้ตรวจจริง
- ระบบทั้งหมดต้อง "ขั้นตอนมาจากคู่มือ" ถ้อยคำคำเตือนด้านความปลอดภัยเป็นเรื่องของผู้ใช้ อย่าแก้เอง
