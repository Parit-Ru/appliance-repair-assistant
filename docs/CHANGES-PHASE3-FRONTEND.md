## 1. ภาพรวม

### ปัญหาที่แก้

เดิมผู้ใช้เลือก "อาการ" ได้เลยโดยระบบไม่รู้ว่าเครื่องของผู้ใช้เป็นรุ่นไหน แต่ขั้นตอนซ่อมในผังมาจาก **คู่มือของแต่ละรุ่น** และต่างกันตามรุ่น พอมีคู่มือหลายไฟล์ (22 ไฟล์ / 644 ผัง) เกิดปัญหาตามที่วัดไว้ใน PLAN §1:

| ปัญหา | หลักฐาน |
|---|---|
| ผลค้นหาซ้ำกัน เป็นอาการเดียวกันจากคนละรุ่น | "ทีวีไม่มีภาพ" → "หาช่องไม่เจอ" ×3 · 144 จาก 365 อาการมีมากกว่า 1 รุ่น |
| ไม่รู้ว่าผู้ใช้ใช้รุ่นไหน จึงอาจได้ขั้นตอนของรุ่นอื่น | ผลค้นหาไม่มีฟิลด์รุ่น · ผังต่างรุ่นมีขั้นตอนต่างกัน (รวมถึงขั้นที่ต้องยืนยันความปลอดภัย) |

### Flow ของผู้ใช้หลังแก้

```
หน้าแรก ──▶ /devices ─────────▶ /devices?category=… ─────▶ /symptoms?manual=… ─────▶ /session/:id
            การ์ดประเภทเครื่อง    รายการรุ่น (พิมพ์เลขรุ่น      ค้นพิมพ์อิสระ หรือ          ตรวจทีละขั้น
            (เฉพาะที่มีคู่มือ)     กรองได้) + "ฉันไม่ทราบรุ่น"    /symptoms/all?manual=…      (แสดงชื่อรุ่น)
```

กติกาที่ตกลงกันแล้ว (D1–D5):

| # | กติกา | ที่ทำในโค้ด |
|---|---|---|
| D1 | ผู้ใช้ไม่รู้รุ่น: แสดงวิธีหาเลขรุ่น + ปุ่ม "ฉันไม่ทราบรุ่น" ที่เตือนและบันทึกค่า · **ห้ามเลือกให้เงียบๆ** | `DevicesPage.tsx` ปุ่มสลับโหมด + กล่องแจ้ง · ผู้ใช้ต้องกดเลือกรุ่นเอง · ส่ง `modelSelection: 'unknown'` ไปบันทึกใน DB |
| D2 | ไม่มีชื่อรุ่น (`display_name`) ให้แสดง `model_pattern` **ห้ามเดาชื่อ** | `manualTitle()` = `displayName ?? modelPattern` |
| D3 | ค้นพิมพ์อิสระได้ แต่เฉพาะรุ่นที่เลือก | `useSymptomSearch` ส่ง `manualId` · backend กรองก่อนจัดอันดับ |
| D4 | ยังไม่ seed คู่มือเพิ่ม | ไม่ได้แตะข้อมูลและ backend |
| D5 | เลือกทีละประเภท | เส้นทางเดียว เครื่อง → รุ่น → อาการ |

เหตุผลของ D3 ที่ใช้อธิบายได้: ประโยชน์คือ **ผลไม่หลุดข้ามรุ่น** (ไม่ใช่เรื่องหน่วยความจำ)

## 4. การไหลของข้อมูล: รุ่นที่เลือกถูกเก็บและส่งต่ออย่างไร

| ขั้น | ที่เก็บ | ค่า | ทำไมเลือกที่นี่ |
|---|---|---|---|
| เลือกประเภท | **URL** `/#/devices?category=…` | ประเภทเครื่อง | กดย้อนกลับของเบราว์เซอร์ถอยจากขั้นรุ่นไปขั้นประเภทได้เอง |
| เลือกรุ่น | **URL** `/#/symptoms?manual=<manual_id>` | รหัสคู่มือ | รีเฟรช กดย้อนกลับ หรือแชร์ลิงก์แล้วยังอยู่รุ่นเดิม |
| บอกว่าไม่ทราบรุ่น | **URL** `&unknown=1` | `'unknown'` (ไม่มี = `'selected'`) | เหตุผลเดียวกัน |
| เริ่ม session | **API** `POST /traversal/sessions` `{graphId, query?, manualId?, modelSelection?}` | — | backend ตรวจว่าผังอยู่ในรุ่นนั้น (ไม่ใช่ → 400 `GRAPH_MANUAL_MISMATCH`) และบันทึก `sessions.model_selection` ลง DB |
| ไปหน้าตรวจ | **navigate state** `{modelSelection}` | `'selected'`/`'unknown'` | หน้า `/session/:id` ไม่มี `?manual=` ใน URL จึงส่งค่าไปกับการนำทาง |
| ค้นหาอาการ | **API** `POST /symptom-search` `{query, manualId}` | — | backend กรองผังตามรุ่นก่อนจัดอันดับ |
| โหลดรายการ | **API** `GET /traversal/manuals` และ `GET /traversal/graphs?manualId=` | — | หน้าเลือกรุ่นและหน้าอาการทั้งหมด |

### ข้อจำกัดที่รู้อยู่

1. **เปิดลิงก์ `/session/:id` ในแท็บใหม่ รุ่นกลายเป็น "เลือกเอง"** เพราะ `modelSelection` ส่งผ่าน navigate state (ไม่อยู่ใน URL และ `SessionResponse` ยังไม่คืนค่านี้) ผลกระทบ: (ก) กล่องเตือน "ไม่ทราบรุ่น" ในหน้านั้นไม่ขึ้น (ข) ถ้ากด "เริ่มอาการนี้ใหม่" ในแท็บนั้น session ใหม่จะถูกบันทึกเป็น `'selected'` ทั้งที่รอบแรกเป็น `'unknown'` — ค่าที่บันทึกตอนเริ่มครั้งแรกถูกต้องเสมอ
2. **หน้าตรวจอาการยังโหลดทุกผัง** (`useGraphs()` ใน `SessionPage.tsx:30`) เพื่อหา `summary` ตอนนี้ DB มี 19 ผัง จึงเล็ก แต่ถ้า seed ครบ 644 ผัง ≈ 222 KB (แคชครั้งเดียว) ทางแก้คือให้ backend ใส่ `manualId` ใน `SessionResponse`
3. **`/symptoms/all` ที่ไม่มี `?manual=`** จะ redirect ไป `/devices` แต่ `useGraphs(undefined)` ถูกเรียกก่อน redirect จึงโหลดทุกผังหนึ่งครั้ง (ไม่มีผลต่อความถูกต้อง เป็นแค่การโหลดเกิน)
4. **ลิงก์ `/symptoms` เปล่าๆ ที่ยังเหลือ** — `SessionErrorNotice.tsx:31` (ปุ่ม "เลือกอาการใหม่") และ `NotFoundPage.tsx:18` — ไม่พัง แต่จะ redirect ไป `/devices` และผู้ใช้ต้องเลือกรุ่นใหม่ (ไม่ได้แก้ เพราะอยู่นอกต้นแบบ)
5. **ปุ่ม "เปลี่ยนรุ่น"** ที่ `AllSymptomsPage` ไป `/devices` (ขั้นเลือกประเภท) ส่วนที่ `SymptomsPage` ไป `/devices?category=…` (ขั้นเลือกรุ่นของประเภทเดิม) ไม่สอดคล้องกันเล็กน้อย
6. **ไม่ได้จำรุ่นล่าสุดใน `localStorage`** (PLAN §2 ระบุเป็นตัวเลือกไม่บังคับ)
7. **ชื่อรุ่นของทีวี/ตู้เย็นบางไฟล์ยังเป็นรหัสเอกสาร** (`display_name`/`model_aliases` ว่าง) การพิมพ์เลขรุ่นจากสติกเกอร์จะหาไม่เจอ แต่ผู้ใช้เลือกจากรายการเต็มได้ (ยังไม่เป็นปัญหา เพราะ DB มีแค่แอร์และเครื่องซักผ้า)
8. **การกรองด้วยเลขรุ่นเป็นแบบคำนำหน้า** พิมพ์ตัวเดียวก็กรอง ใช้กรองรายการเท่านั้น ผู้ใช้ต้องกดเลือกรุ่นเอง

### ที่ "ผ่านเครื่องตรวจ" (ตรวจแล้ว)

- ชนิดข้อมูลทั้งโปรเจกต์ (`tsc -b`) และกฎของ lint (`eslint src` รวมกฎลำดับการเรียก hook)

### ที่ "ยังไม่ได้ดูด้วยตา" (ยังไม่ได้ตรวจ)

- **ยังไม่ได้เปิดเบราว์เซอร์จริง** ทั้งบนคอมพิวเตอร์และมือถือ · ยังไม่ได้ตรวจกับโปรแกรมอ่านหน้าจอ
- **ยังไม่ได้เรียก backend จริง** เทสต์ใช้ข้อมูลจำลองเท่านั้น เพราะ `/traversal/manuals` บน Render ยังเป็น 404 (ยังไม่ได้ push)
- `POST /traversal/sessions` ที่ส่ง `modelSelection` ยังไม่เคยทดสอบกับ DB จริง (เขียนแถวลง `sessions` ที่ใช้ร่วมกับ FixStep)
- ไม่ได้รัน `npm run deploy` และไม่ได้ push

### รายการตรวจด้วยตา 8 ข้อ

- [ ] หน้าแรก: ปุ่มไป `/devices` · "รองรับตอนนี้" แสดงรุ่นละแถวและกดเข้ารุ่นได้

- [ ] กด "ฉันไม่ทราบรุ่น": ช่องพิมพ์หาย + ขึ้นกล่องแจ้ง + แสดงทุกรุ่น · เลือกแล้ว URL มี `unknown=1` · หน้าตรวจอาการมีกล่องแจ้ง
- [ ] เปิด `/#/symptoms` (ไม่มี manual) → เด้งไป `/devices`
- [ ] ค้น "แอร์ไม่เย็น" ในรุ่นแอร์ → ผลมีแต่ผังของรุ่นนั้น
- [ ] เดินจนจบ → "ตรวจอาการอื่น" กลับ `/symptoms?manual=…` เดิม (รวม `unknown=1` ถ้าเลือกแบบไม่ทราบ)
- [ ] ปิด backend ระหว่างอยู่หน้า `/devices` → ขึ้นกล่องข้อผิดพลาด + ปุ่มลองอีกครั้ง
- [ ] มือถือ: แถวรุ่นกดง่าย (สูง ≥ 56px) ไม่มีแถบเลื่อนแนวนอน

## 7. คำถามที่กรรมการน่าจะถาม

**ทำไมไม่เลือกรุ่นให้ผู้ใช้เงียบๆ (เช่น เดาจากอาการหรือเลือกรุ่นแรก)?**
ขั้นตอนซ่อมมาจากคู่มือของแต่ละรุ่นและต่างกัน ถ้าระบบเลือกผิดโดยผู้ใช้ไม่รู้ ผู้ใช้อาจทำตามขั้นตอนของเครื่องอื่น โดยเฉพาะขั้นที่เกี่ยวกับความปลอดภัย ระบบจึงให้ผู้ใช้เลือกเองเสมอ และถ้าไม่ทราบรุ่นก็บอกตรงๆ พร้อมเตือน

**ถ้าผู้ใช้ไม่รู้รุ่นจริงๆ จะทำอย่างไร?**
กด "ฉันไม่ทราบรุ่น" ระบบบอกวิธีดูเลขรุ่น (สติกเกอร์ที่ตัวเครื่อง ปกคู่มือ หน้าจอข้อมูลเครื่อง) และเตือนว่าขั้นตอนอาจไม่ตรง ผู้ใช้เลือกรุ่นใกล้เคียงเอง ระบบบันทึกค่า `unknown` ไว้ใน session เพื่อแยกเคสตอนวัดผล

**ทำไมเก็บรุ่นไว้ใน URL ไม่เก็บใน state หรือ localStorage?**
ผู้ใช้กดย้อนกลับ รีเฟรช หรือแชร์ลิงก์แล้วต้องอยู่รุ่นเดิม state ในหน้าจอหายตอนรีเฟรช ส่วน URL ทำให้ทุกหน้ารู้รุ่นโดยไม่ต้องมีที่เก็บกลาง และตรวจสอบย้อนหลังได้

**ถ้าหน้าเว็บส่งผังผิดรุ่นมา จะเกิดอะไรขึ้น?**
backend ตรวจซ้ำว่าผังที่เริ่มอยู่ในรุ่นที่ระบุจริงหรือไม่ ถ้าไม่ใช่ตอบ 400 `GRAPH_MANUAL_MISMATCH` และไม่สร้าง session หน้าเว็บแสดงข้อความ "อาการนี้ไม่ใช่ของรุ่นที่เลือก" การตรวจฝั่งเซิร์ฟเวอร์ทำให้ไม่ต้องเชื่อใจหน้าเว็บ

**ทำไมไม่ให้ LLM ช่วยเดาชื่อรุ่นหรือแปลงเลขรุ่น?**
ตามหลักของโครงการ ลำดับขั้นตอนและข้อมูลรุ่นต้องมาจากคู่มือโดยตรง ชื่อรุ่นที่ยังไม่มีข้อมูลจึงแสดงรหัสในคู่มือไปก่อน ผู้พัฒนาเติม `display_name` จากคู่มือเอง (D2)

**ระบบรองรับกี่รุ่น?**
ตามข้อมูลที่ seed บนเว็บจริงตอนนี้ มีแอร์และเครื่องซักผ้า WT10J7 (19 ผัง) ข้อมูลคู่มืออีกหลายไฟล์พร้อมในโปรเจกต์แต่ยังไม่ seed (D4) จนกว่าหน้าเลือกรุ่นจะใช้งานได้ครบ

**ข้อมูลที่เก็บว่า "ไม่ทราบรุ่น" เอาไปทำอะไร?**
ใช้แยกเคสตอนวัดผล ว่าผู้ใช้ที่ไม่ทราบรุ่นทำสำเร็จมากน้อยกว่าผู้ใช้ที่ทราบรุ่นแค่ไหน (ยังไม่ได้วัด)

**ข้อจำกัดที่ยังมีคืออะไร?**
ดู §4 ข้อ 1–8 โดยสำคัญคือ ยังไม่ได้ทดสอบบนเบราว์เซอร์จริงและยังไม่ได้เรียก backend จริงหลังแก้
