# โมเดล embedding และ "model" มาจากไหน — อธิบายกรรมการอย่างไร

> **หมายเหตุชื่อโฟลเดอร์:** เดิมชื่อ `backend/model-slim/` เปลี่ยนเป็น `backend/model/` เมื่อ 20 ต.ค. 2569 (เนื้อไฟล์เป็นโมเดลที่ตัดคำศัพท์แล้วเหมือนเดิม — เปลี่ยนแค่ชื่อ) เอกสารเก่า/commit เก่าจะเรียก `model-slim`
> แยก 3 ระดับความมั่นใจ: ✅ ยืนยันจากไฟล์ในรีโป · 🟡 ความรู้ทั่วไปของผม (ให้เปิดหน้า Hugging Face ตรวจก่อนอ้าง) · ⚠️ ไม่ทราบ

## 1. สรุปที่พูดได้ใน 30 วินาที

> "ระบบค้นอาการด้วย embedding โมเดลสำเร็จรูป **paraphrase-multilingual-MiniLM-L12-v2** ซึ่งเป็นโมเดลหลายภาษาที่เปิดให้ใช้ ไม่ได้ฝึกเอง เราใช้เวอร์ชันที่แปลงเป็น ONNX และลดขนาดเป็น 8 บิต (q8) จากบัญชี Xenova บน Hugging Face แล้ว **ตัดตารางคำศัพท์ให้เหลือเฉพาะภาษาไทย ภาษาอังกฤษ และเครื่องหมาย** เพื่อให้ไฟล์เล็กลง ส่วนที่เหลือของโมเดล (น้ำหนักทุกชั้น) ไม่แตะ และเรามีขั้นตรวจว่าข้อความที่ระบบใช้ค้นได้เวกเตอร์เหมือนเดิมทุกไบต์"

## 3. "ตัดตารางคำศัพท์" คืออะไร (ภาษาคน)

โมเดลแปลงข้อความเป็นเวกเตอร์ โดยเริ่มจากแปลง "ชิ้นคำ" (token) แต่ละชิ้นเป็นเลขรหัส แล้วดูแถวของตารางที่ตรงกับรหัสนั้น ตารางนี้ใหญ่เพราะรองรับ 50+ ภาษา (จีน ญี่ปุ่น อาหรับ ฯลฯ) ซึ่งระบบเราไม่ต้องใช้ — คู่มือและคำค้นเป็นไทย/อังกฤษ

สคริปต์ทำ 5 อย่าง (จากหัวไฟล์ `slim_model.py`):
1. เลือกเก็บ token ที่ทุกตัวอักษรเป็นไทย / ASCII / เครื่องหมาย + token พิเศษ (`<s> <pad> </s> <unk>` คง id 0–3)
2. กำหนด id ใหม่เรียงต่อกันตาม id เดิม
3. ตัดแถวของตารางคำศัพท์ในไฟล์ ONNX ให้เหลือเฉพาะแถวที่เก็บ — **น้ำหนักส่วนอื่นเหมือนเดิมทุกไบต์** (สคริปต์ตรวจ)
4. เขียน `tokenizer.json`, `config.json`, `tokenizer_config.json` ใหม่ให้ id ตรงกัน
5. **ตรวจตัวเอง:** ทุกข้อความที่ระบบใช้ค้นหา ต้องตัดคำได้ไม่มีตัวที่หลุดเป็น `<unk>` และแถวที่ดึงจากตารางใหม่ต้องเท่ากับตารางเดิมทุกไบต์ ถ้าไม่ผ่านสคริปต์จบด้วย exit code 1 (เหตุผลที่ผลเวกเตอร์ไม่เปลี่ยน: ผลของโมเดลขึ้นกับแถวที่ดึงมาและน้ำหนักชั้นอื่น ไม่ขึ้นกับเลข id)

## 4. คำถามที่น่าจะโดน

**ทำไมไม่ฝึกโมเดลเอง?** ไม่ได้ฝึก — ใช้โมเดลสำเร็จรูปที่เปิดให้ใช้ เพราะงานค้นอาการต้องการแค่ "วัดความใกล้ของความหมาย" ซึ่งโมเดลนี้ทำได้อยู่แล้ว และเราไม่มีข้อมูลฝึกที่ตรวจแล้ว (ไม่มีชุดทดสอบที่มนุษย์ตรวจ ตามที่บันทึกไว้ใน STUDY_GUIDE §3)

**ทำไมเลือกโมเดลนี้เทียบกับตัวอื่น?** ⚠️ ไม่มีบันทึกการเปรียบเทียบในรีโป ที่ตอบได้คือ: เป็นโมเดลหลายภาษา (ชื่อระบุ multilingual) รองรับไทย ขนาดเล็กพอรันใน backend โดยไม่ต้องมี GPU/บริการภายนอก — อย่าอ้างว่าทดลองเทียบแล้ว

**ทำไมต้องตัด?** ⚠️ ไม่มีคำอธิบายเหตุผลโดยตรงในสคริปต์ ที่อนุมานได้จากโค้ด: ระบบรันบน Render แผน free และ `symptom-search.service.ts` ระบุว่าปิดการค้นเป็นค่าเริ่มต้นเพื่อกัน "หน่วยความจำเกินแล้วเซิร์ฟเวอร์ล่ม" — การลดขนาดโมเดลสอดคล้องกับเรื่องนี้ แต่ **ไม่ใช่ข้อความที่ผู้พัฒนาเขียนไว้** ให้ตอบตามตัวเองว่าทำเพื่อลดขนาด/หน่วยความจำ

**ตัดแล้วคุณภาพเปลี่ยนไหม?** สำหรับข้อความไทย/อังกฤษที่อยู่ในชุดที่เก็บ — ไม่เปลี่ยน (ตรวจเป็นไบต์ต่อไบต์ในขั้น 5) · **ข้อแลกเปลี่ยนที่ต้องยอมรับ:** อักษรนอกชุด (จีน ญี่ปุ่น ฯลฯ) กลายเป็น `<unk>` คือโมเดลมองไม่เห็นตัวอักษรเหล่านั้น (สคริปต์พิมพ์ตัวอย่างข้อนี้ไว้ตอนรัน) · ไม่ได้ทดสอบกับคำค้นของผู้ใช้จริงนอกชุดข้อความของระบบ

**ไฟล์โมเดลมาอยู่ใน repo ได้อย่างไร?** ไฟล์ทั้ง 4 ถูก track ใน git (ONNX ~56 MB เป็นไฟล์ที่ใหญ่ที่สุดใต้ `backend/`) เพื่อให้ Render มีไฟล์ตอน build โดยไม่ต้องดาวน์โหลดจากเน็ตตอนบูต

**ทำซ้ำได้ไหม?** ⚠️ ตอนนี้ **รันสคริปต์ซ้ำตรงๆ ไม่ได้**: (1) สคริปต์ชี้ไฟล์ผังแอร์ที่ลบแล้ว และคำค้นตัวอย่างเป็นเรื่องแอร์ (2) ต้องมีโมเดลต้นฉบับใน `backend/model-cache/` ซึ่งไม่มีในเครื่อง/รีโป และสคริปต์ดาวน์โหลด (`measure-embedding.js`) ไม่มีแล้ว — ถ้าจะทำซ้ำ ต้องดาวน์โหลดโมเดลต้นฉบับจาก Hugging Face มาวางที่ `backend/model-cache/Xenova/paraphrase-multilingual-MiniLM-L12-v2/` แล้วแก้ `MANUAL_FILE` กับคำค้นตัวอย่างให้ใช้ผังที่ยังมี
