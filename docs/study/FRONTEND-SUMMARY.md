# สรุปท้ายเล่ม: frontend (อ่านครบ 86 ไฟล์ใน `frontend/src`)

สรุปจากการอ่านโค้ดจริงทีละไฟล์ ยังไม่เคยรันเว็บ ทุกข้อด้านล่างจึงเป็น "อ่านจากโค้ด" ไม่ใช่ "ทดสอบแล้ว"
คำถามพร้อมเฉลยละเอียดอยู่ใน `QA-WALKTHROUGH-FRONTEND.md` (ส่วน A, B, D)

## 1. ภาพรวมสถาปัตยกรรมใน 6 ข้อ

- **เทคโนโลยี:** React 19 + Vite 8 + TanStack Query 5 + React Router 7 + Tailwind 3 คุยกับ backend Express ผ่าน `api/http.ts` ที่เดียว
- **หน้าจอไม่ตัดสินใจเรื่องขั้นตอนการตรวจ:** backend เป็นคนเดินแผนผังขั้นตอน หน้าจอส่งแค่การกระทำ 4 แบบ (`answer`, `continue`, `confirm_safety`, `input`) แล้วแสดงโหนดที่ backend ส่งกลับมา (`SessionPage` → `StepView`)
- **ข้อมูลจากเซิร์ฟเวอร์อยู่ใน TanStack Query ทั้งหมด:** `api/queries.ts` เป็นศูนย์รวม hook มีนโยบายแคชต่างกันตามชนิดข้อมูล (แผนผังและคู่มือ `staleTime: Infinity`, ร่างที่กำลังสร้างดึงซ้ำทุก 3 วินาที)
- **ตัวตนผู้ใช้ 3 ชั้น:** `AuthContext` (guest / verifying / user), `useIdentity()` ใส่ในคีย์แคช, `ownerHeaders()` ส่ง `X-Client-Id` ให้ผู้ใช้ที่ไม่ล็อกอิน และ `queryClient.clear()` เมื่อล็อกอิน/ออก/โดน 401
- **ข้อผิดพลาดมีจุดแปลจุดเดียว:** `lib/errors.ts` (`describeError`) แปลรหัส error เป็นข้อความไทยและบอกวิธีกู้ แล้ว `ErrorNotice` แสดงผล
- **ด่านฝั่งหน้าจอเป็น UX เสมอ ไม่ใช่ความปลอดภัย:** `AdminRoute`, ช่องติ๊กยืนยันความปลอดภัย, ปุ่มเผยแพร่ร่าง ทั้งหมด backend ตรวจซ้ำ

## 2. ลำดับการไหลหลักที่ต้องเล่าให้ได้

- **ตรวจอาการ:** เลือกอุปกรณ์ (`DevicesPage`) → เลือกรุ่น (`modelSelection`) → ค้นอาการ (`SymptomsPage`) → `useStartSymptom` สร้าง session → `SessionPage` วนถามตอบจนถึงโหนดสุดท้าย → ส่งผลลัพธ์ (`OutcomeForm`)
- **ด่านความปลอดภัย:** `StepView` เรียงลำดับ ผลสุดท้าย → ด่านความปลอดภัย → จุดตรวจ → ช่องกรอก → คำสั่งปกติ ช่องติ๊กกันความพลาด แต่ backend ต้องได้ `confirm_safety` ชัดเจนจึงจะไปต่อ
- **ประวัติ:** `HistoryPage` แบ่งหน้า, ลบ (ตรวจเจ้าของที่ backend), ให้คะแนนความเห็น
- **ผู้ดูแล:** สถิติ (กราฟสร้างด้วย CSS เอง ไม่ใช้ไลบรารีกราฟ), ความเห็นผู้ใช้ (ตัวกรองเก็บใน URL), ร่างแผนผังขั้นตอน
- **ท่อร่างแผนผังขั้นตอน:** อัปโหลด PDF → AI ร่าง → backend ตรวจ → ผู้ดูแลตรวจเทียบหน้าต้นฉบับ แก้ JSON ตรวจใหม่ → ติ๊กรับรอง → เผยแพร่ (PDF ไม่ถูกเก็บ)

## 3. ไฟล์ที่ควรเปิดดูซ้ำก่อนสอบ

- ⭐ `SessionPage.tsx` (`handleAction`: กันกดซ้ำด้วย ref, `onSuccess` ต่อเส้นทาง)
- ⭐ `api/queries.ts` (นโยบายแคช, `setQueryData` กับ `invalidateQueries`)
- ⭐ `components/auth/AuthProvider.tsx` (verify token, ตัวจัดการ 401)
- ⭐ `lib/errors.ts` (ตัดสินจากรหัส ไม่ใช่ข้อความจากเซิร์ฟเวอร์ ยกเว้นรหัสร่าง 3 ตัว)
- ⭐ `DraftActions.tsx` + `lib/draftView.ts` (`publishGate`)
- รอง: `api/http.ts`, `lib/authStorage.ts`, `StepView.tsx`, `SafetyGateStep.tsx`

## 4. คำถามที่กรรมการน่าถาม (ตอบสั้นๆ ได้จากข้างบน)

- ทำไมให้ backend เดินแผนผัง ไม่ให้หน้าจอเดินเอง → ผลลัพธ์ตรวจสอบได้ที่เดียว กันหน้าจอถูกแก้ข้ามด่านความปลอดภัย
- ผู้ใช้ไม่ล็อกอินแยกจากกันอย่างไร → `X-Client-Id` ที่สร้างและเก็บในเบราว์เซอร์ (`lib/clientId.ts`)
- ถ้า token หมดอายุเกิดอะไร → `http.ts` ได้ 401 เฉพาะตอนที่ส่ง token ไป → ตัวจัดการใน `AuthProvider` ล้างแคชและพาไปล็อกอิน
- `AdminRoute` กันคนไม่ใช่ admin ได้จริงไหม → ไม่ กันแค่หน้าจอ ตัวกันจริงคือ backend
- ทำไมไม่ใช้ไลบรารีกราฟ → ข้อมูลเรียบง่าย ลดการพึ่งพาไลบรารี (`BarList`, `DailyBars` ใช้ CSS)
- ทำไมต้องเตือนร่าง AI → ร่างอาจผิดจากคู่มือ จึงต้องมีคนตรวจเทียบต้นฉบับก่อนเผยแพร่

## 5. ข้อสังเกตที่เจอแต่ยังไม่แก้ (แก้เมื่อสั่งเท่านั้น)

**น่าจะมีผลต่อการใช้งาน (วิเคราะห์จากโค้ด ยังไม่ได้ลองจริง):**
- `DraftActions` ไม่รีเซ็ตช่องติ๊ก "ตรวจแล้ว" หลังตรวจ JSON ใหม่ ต่างจาก `DraftJsonEditor` ที่ใช้ `key={draft.updatedAt}` (`AdminDraftReviewPage.tsx:111`)
- หลังเผยแพร่สำเร็จ สถานะร่างเปลี่ยนเป็น `published` แล้ว `DraftActions` อาจหายไป ทำให้กล่องผลเผยแพร่แสดงชั่วครู่หรือไม่เห็น (ต้องรันดู)

**ข้อความ/เอกสาร:**
- `AdminDraftReviewPage.tsx:72` อ้าง `docs/authoring-step5.md` ที่จริงคือ `docs/authoring/authoring-step5.md`
- คอมเมนต์ล้าสมัยใน `Notice.tsx` และ `modelSelection.ts:4`

**ความสม่ำเสมอ/การเข้าถึง:**
- ค่าคงที่ที่ก๊อปมือระหว่าง frontend กับ backend (กติกาฟอร์มสมัครสมาชิก, ข้อจำกัดอัปโหลด, วันเก็บข้อมูล, ความยาวเหตุผลปฏิเสธ 300) ตรงกันเท่าที่เทียบแล้ว แต่ต้องแก้สองที่ถ้าเปลี่ยน
- `INVALID_QUERY` เขียนเลข 200 ตรง ๆ แทนค่าคงที่
- `NotFoundPage` ลิงก์ไป `/symptoms` ซึ่งต้องเด้งต่อ
- หน้าสถิติลำดับหัวข้อข้ามจาก `h1` ไป `h3`

## 6. ยังไม่ได้ตรวจ

- **C2:** `SessionPage` ยิง `GET` ซ้ำหลังเขียนแคชหรือไม่ ต้องดู Network tab ตอนรันจริง
- ไม่เคยรันเว็บ ไม่เคยล็อกอินเป็น admin ไม่เคยอัปโหลด/เผยแพร่จริง
- ฝั่ง backend อ่านเฉพาะส่วนที่ใช้เทียบ ยังไม่ได้อ่าน `drafts.service.ts`, `drafts.routes.ts`, `graph-validator.ts` (⭐⭐ ค้างใน `READING-PROGRESS.md`)
- `READING-PROGRESS.md` ส่วน Frontend ยังเขียนว่า "ยังไม่เริ่ม" เพราะยังไม่มีคำสั่ง "mark ไว้"
