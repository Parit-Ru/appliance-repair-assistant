# การตัดสินใจ: เกณฑ์คะแนนค้นอาการ (MATCH_THRESHOLD) 0.55 → 0.7

**วันที่:** 14 พ.ย. 2569 · **ผู้ตัดสินใจ:** เจ้าของโปรเจกต์ (เลือก 0.7 จากตัวเลือก 0.65 / 0.7)
**ที่แก้:** `backend/src/symptom-search/symptom-search.service.ts` (`MATCH_THRESHOLD`) และค่าซ้ำใน `backend/scripts/study-measure.js`
**ไม่เปลี่ยน:** `MAX_RESULTS = 3`

## เดิมเป็นอย่างไร
0.55 เป็นค่าที่ยืมมาจากงานก่อนหน้า ไม่มีการทดลองเลือกในโปรเจกต์นี้ (ดู STUDY_GUIDE ข้อ Q3) · ผลวัดเก่าชี้ว่าไม่มีเกณฑ์เดียวที่แยก "นอกขอบเขต" ได้ดี

## เหตุผลที่เลือก 0.7
- ตัดข้อความนอกเรื่องที่หลุดผ่านจาก 36% เหลือ 7%
- เคสถูกที่หายเท่ากับ 0.65 (RF22 0.586 และ MW18 0.641 หาย · ที่เหลือ ≥ 0.758) ไม่เสียเพิ่ม
- ยอมแลกกับคู่ที่ไม่เหลือผลเลยเพิ่มจาก 4.7% เป็น 15.6% — ผู้ใช้ยังเลือกจาก "อาการทั้งหมด" ได้เสมอ (ผลเป็นการเตือน ไม่ใช่ทางตัน)
- ไม่เลือก 0.75+ เพราะคู่ที่ไม่เหลือผลพุ่ง (25.8%) และ 0.80 เริ่มทำเคสถูกหาย (25/31)

## ข้อจำกัด (ต้องพูดตรง ๆ ตอนสอบ)
- ชุดลบผู้พัฒนาแต่งเอง ไม่ผ่านผู้เชี่ยวชาญ บางข้อถกได้ว่าควรผ่านหรือไม่ (เช่น "เสีย") → ตัวเลขใช้เทียบเกณฑ์ด้วยกัน **ไม่ใช่ความแม่นยำ**
- ชุดบวกมีผังถูกแค่ 31 เคส ความต่างระหว่าง 0.60–0.75 เกิดจาก 1–2 เคส → บอกทิศทาง ไม่ใช่จุดที่ดีที่สุดแน่นอน
- คะแนนไม่ได้บอกว่าถูก: เคสผังถูกใน top 3 มีคะแนนสูงสุดเฉลี่ย 0.876 เคสที่พลาด 0.872 → เกณฑ์เป็นแค่ตัวกรองข้อความนอกเรื่อง
- "สวัสดี" ยังได้สูงสุด 0.730 จึงยังผ่าน 0.7 ในบางคู่มือ — เกณฑ์อย่างเดียวแก้ไม่หมด
- ยังไม่ได้รัน `eval/run-real-cases.ts` ซ้ำด้วยเกณฑ์ใหม่ (ต้องใช้ DB `fixbot_eval`) และผลเก่าใน `eval/results/*` ยังบันทึกเกณฑ์ 0.55

## คำตอบกรรมการ
> เกณฑ์เดิม 0.55 ยืมมาโดยไม่ได้ทดลอง ผมจึงวัดเทียบ 0.50–0.80 กับอาการจริง 99 เคสและข้อความนอกขอบเขต 878 คู่ แล้วเลือก 0.7 เพราะลดข้อความนอกเรื่องที่หลุดจาก 36% เหลือ 7% โดยเคสที่ผังถูกหายเพิ่มแค่ 2 ใน 31 เคส ชุดทดสอบฝั่งนอกขอบเขตผมแต่งเอง จึงถือเป็นการเทียบเกณฑ์ ไม่ใช่การวัดความแม่นยำ และผู้ใช้ยังเลือกอาการเองจากรายการได้เสมอ
