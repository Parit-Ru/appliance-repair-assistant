> เขียนเมื่อ 7 พ.ย. 2569 · ข้อความอาการทุกตัวอย่างในไฟล์นี้ **ผมรันกับตัวค้นหาของจริง** (โมเดลฝังความหมายและฟังก์ชัน cosine ตัวเดียวกับที่ระบบใช้ ป้อนข้อมูลจาก `data/manuals/*.json` แทนฐานข้อมูล) แล้วคัดเฉพาะที่ได้ผลชัด พร้อมคะแนนจริง · ขั้นที่ตอบทีละสถานะ ผมรัน **เครื่องสถานะของจริง** เดินจนจบ (ผลอยู่ในข้อ 4)
> **สิ่งที่ผมยังไม่ได้ทำ:** ไม่ได้เปิดเว็บเดโมทั้งระบบ (หน้าเว็บ + backend + ฐานข้อมูล) ให้ดูด้วยตา เพราะ `backend/.env` ชี้ Aiven ซึ่งเป็นฐานจริงที่ใช้ร่วมกับโปรเจกต์ FixStep (ตาม `docs/HANDOFF-NEW-MACHINE.md:§2`) และห้ามเขียนข้อมูลลงฐานนั้น — ข้อความบนหน้าจอที่เขียนในตารางด้านล่างจึงมาจากโค้ดหน้าเว็บ ไม่ใช่จากการดูหน้าจอจริง **ซ้อมจริงอย่างน้อย 1 รอบก่อนสอบ**

## 1. เตรียมเครื่องตัวเอง (ทำก่อนวันสอบ ไม่ใช่ในห้อง)

### 1.1 ฐานข้อมูลเดโมในเครื่อง (ห้ามใช้ Aiven)

กฎ: `DB_HOST` ต้องเป็น `localhost` และ `DB_NAME` มีคำว่า `demo` — สคริปต์ `backend/scripts/reset-demo-db.js` (ไฟล์ใหม่ ยังไม่ commit) ตรวจสองข้อนี้ให้และ **ลบฐานทิ้งแล้วสร้างใหม่** จึงใช้ได้เฉพาะฐานเดโมเท่านั้น

ตรวจว่า `.env` ชี้เครื่องตัวเองหรือไม่ (พิมพ์แค่ True/False ไม่พิมพ์ค่า):

```powershell
cd C:\Users\SPS\Desktop\499\appliance-repair-assistant\backend
Select-String -Path .env -Pattern '^DB_HOST=(localhost|127\.0\.0\.1)\s*$' -Quiet
```

ถ้าได้ `False` แปลว่ายังชี้ฐานบนคลาวด์ → **หยุด** สำรอง `.env` เดิมไว้นอก repo แล้วตั้ง `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` (ชื่อมี `demo`, เช่น `appliance_demo`) ให้ชี้ MySQL ในเครื่อง · `JWT_SECRET` (≥ 32 ตัวอักษร), `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_DISPLAY_NAME` ต้องมีด้วย · ตั้ง `SYMPTOM_SEARCH_ENABLED=true` · ชั้นเรียบเรียงถ้อยคำ (`REPHRASE_ENABLED`, `GROQ_API_KEY`, `GROQ_MODEL`) ตั้งหรือไม่ตั้งก็ได้ (ข้อ 5)

สร้างฐาน + ตาราง + บัญชี admin + ข้อมูล (ใช้ 3 คู่มือที่ผมทดสอบแล้ว ไม่ต้อง seed ทั้ง 25 เล่ม):

## 2. เตรียมบน Render (ถ้าจะโชว์ตัวนี้) — cold start

**ที่ผมวัดจริงเมื่อ 7 พ.ย. 2569** (GET อย่างเดียว ไม่เขียนข้อมูล):

| ช่วง | เวลา |
|---|---|
| คำขอแรกหลังเซิร์ฟเวอร์หลับ (`GET /health`) | **32 วินาที** แล้วตอบ `200 ok` |
| จากนั้น `GET /symptom-search/status` | `state: "loading"` อยู่ราว **2 นาที** (ดัชนี 4,129 ข้อความจาก 670 ผัง) แล้วเป็น `ready` โดย `loadMs = 114,458` |
| ระหว่าง `loading` ถ้าผู้ใช้กดค้นหา | ระบบตอบ 503 `SEARCH_NOT_READY` "ระบบค้นหากำลังเริ่มทำงาน" (`symptom-search.service.ts:15,171`) |

→ **รวมแล้วหลังหลับ ต้องรอราว 2.5 นาทีกว่าจะค้นอาการได้** (ตัวเลขตัวอย่างเดียว ไม่ใช่ค่าคงที่) · หน้าเว็บมีกล่อง "เซิร์ฟเวอร์กำลังเริ่มทำงาน — ถ้าไม่มีคนใช้มาสักพัก เซิร์ฟเวอร์ต้องตื่นก่อน" (`SlowServerNotice.tsx`) แต่ไม่มีกล่องบอกว่า "ค้นหายังไม่พร้อม" ต่างหาก

**ปลุกก่อนเข้าห้อง** (เริ่ม ≥ 10 นาทีก่อน แล้ววนจนเป็น `ready`):

```powershell
$base = "https://appliance-repair-assistant.onrender.com"
Invoke-RestMethod "$base/health"
do { $s = Invoke-RestMethod "$base/symptom-search/status"; Write-Host (Get-Date -Format HH:mm:ss) $s.state; if ($s.state -ne "ready") { Start-Sleep -Seconds 10 } } while ($s.state -ne "ready")
```

เซิร์ฟเวอร์ฟรีจะหลับอีกถ้าไม่มีคนใช้ ให้ยิง `/health` ซ้ำทุก ~10 นาทีจนถึงเวลาสอบ (ตามเอกสารของ Render แพ็กเกจฟรีหลับเมื่อไม่มีคำขอราว 15 นาที — ตรวจตัวเลขจริงในแดชบอร์ดของคุณ) · URL เดโมที่ใช้จริงตอนนี้คือ `https://appliance-repair-assistant.onrender.com` (ตอบ `/health` ได้ · ชื่อ service ใน `render.yaml` คือ `appliance-repair-backend` แต่ลองยิง `appliance-repair-backend.onrender.com` ได้ 404 จึงใช้ URL แรก)

**ข้อควรระวังเฉพาะ Render:** หน้าเลือกรุ่นของตู้เย็นมีรายการ **`demo_b` (รุ่น "a")** และ **`demo_rb6000d`** ค้างอยู่ (ข้อมูลทดลอง) อย่าเลือกตอนเดโม หรือให้คุณลบ/ซ่อนก่อนสอบ · ทีวีรุ่น KM2DVBADN **ไม่มี** บน production

### 4.1 วิธี "ลองข้ามคำเตือนความปลอดภัย" ให้เห็นผลจริง

บนหน้าจอ: ปุ่มยืนยันกดไม่ได้จนกว่าจะติ๊ก — แสดงเป็นขั้นแรก · จากนั้นพิสูจน์ว่าด่านอยู่ที่ backend ด้วย PowerShell (ใช้บัญชีผู้ใช้ที่สมัครไว้ใน 1.3 และ session ที่หยุดอยู่ที่ขั้นความปลอดภัย; ก๊อป session id จาก URL `/session/<id>` ของหน้าเว็บ):

```powershell
$base = "http://localhost:3000"
$body = @{ email = "demo@example.com"; password = "DemoPass123" } | ConvertTo-Json
$login = Invoke-RestMethod "$base/auth/login" -Method Post -ContentType "application/json" -Body $body
$h = @{ Authorization = "Bearer $($login.accessToken)" }
$sid = Read-Host "วาง session id จาก URL"
try {
  Invoke-RestMethod "$base/execution/sessions/$sid/actions" -Method Post -Headers $h -ContentType "application/json" -Body '{"type":"continue"}'
} catch { $_.ErrorDetails.Message }
```

ผลที่ควรได้ (รูปแบบจาก `common/error-handler.ts:15,36`): `{"statusCode":400,"code":"SAFETY_CONFIRMATION_REQUIRED","message":"สถานะ 'n1f' เป็น safety_critical ต้องส่ง action 'confirm_safety' เท่านั้น จะใช้ 'continue' เฉยๆ ไม่ได้"}` · ถ้า session นั้นของ guest (ไม่ได้ล็อกอิน) ให้ใส่ header `X-Client-Id` แทน token (ค่าจาก `localStorage` คีย์ `fixstep.clientId`)

**ที่ผมทดสอบแล้วจริง** (รันเครื่องสถานะของจริงบนผังนี้ ไม่ผ่านเครือข่าย): เริ่มที่ `n1` → ตอบ `answer yes` ไป `n1f` (ต้องยืนยันความปลอดภัย) → ส่ง `continue` ได้ `SafetyConfirmationRequiredError` → ส่ง `answer` ผิดชนิดได้ `InvalidActionError` → ส่ง `confirm_safety` ไป `n1v` → ตอบ yes ไป `n_resolved` (สถานะสิ้นสุด ผล `user_fixed`) → ส่ง action ซ้ำได้ `SessionAlreadyCompletedError`

## 5. แผนสำรอง

### 5.1 ค้นหาใช้ไม่ได้ (503 กำลังเริ่มทำงาน / ไม่พร้อม)
เมนู **อาการทั้งหมด** (`/symptoms/all`) เลือกผังจากรายการโดยไม่ต้องใช้ตัวค้นหา — พูดว่า "ผู้ใช้เลือกจากรายการเองได้ ค้นหาเป็นทางลัด ไม่ใช่ทางเดียว" (ระบบไม่เปิดตัวค้นหาจนกว่าโมเดลโหลดเสร็จ จึงไม่มีทางที่ตัวค้นหาจะตอบมั่ว)

### 5.2 เน็ตหรือ Render ล่ม
- ใช้ **ตัวเลือก A (เครื่องตัวเอง)**: ตัวค้นหาทำงานออฟไลน์ได้ (โมเดลอยู่ใน `backend/model/`) · ชั้นเรียบเรียงถ้อยคำ (Groq) จะล้มและ **ระบบแสดงข้อความต้นฉบับแทน** — เป็นจุดที่ใช้พิสูจน์ได้ว่าความปลอดภัยไม่พึ่ง LLM
- ถ้าเครื่องตัวเองก็ไม่ขึ้น: ใช้ภาพหน้าจอชุดที่เตรียมไว้ใน `Thes\คู่มือผู้ใช้_appliance-repair-assistant.docx` (23 ภาพ ครอบคลุมทุกขั้นข้างบน) แล้วเล่าเป็นภาพนิ่ง บอกกรรมการตรงๆ ว่าเดโมสดไม่ได้เพราะอะไร
- เตรียมหน้าจอสุดท้ายนี้ไว้ในแท็บแยกก่อนเข้าห้อง (ไม่ต้องล็อกอินใหม่)

### 5.3 อย่าทำสดในห้อง
- **อัปโหลด PDF ให้ AI ร่างสด**: เรียก Groq จริง ใช้เวลาหลายสิบวินาที (timeout ค่าเริ่มต้น 60 วินาที `draft-llm.client.ts:6`) · โควตาของ key นี้ ~12–16 คำขอ/นาที และใช้ได้เฉพาะโมเดล `openai/gpt-oss-20b` (`docs/HANDOFF-NEW-MACHINE.md:§7`) · **ฝั่ง Express ยังไม่เคยทดสอบกับ Groq จริง** (`docs/HANDOFF-THESIS-VS-PROPOSAL.md:§6 ข้อ 3`) → เตรียมร่างที่สถานะ "รอตรวจ" ไว้ล่วงหน้า และถ้ากรรมการขอดูอัปโหลดจริง ให้ลองครั้งเดียวกับ PDF 1–3 หน้า (จำกัด 10 หน้า/ร่าง · PDF ≤ 10 MB) และเตรียมคำตอบว่าถ้าล้มจะเห็นข้อความอะไร
- **ลบ/แก้ผังบน Render** (ฐานที่ใช้ร่วมกับ FixStep)
- **เผยแพร่ร่างบนฐานที่มีข้อมูลจริง** เผยแพร่ได้เฉพาะคู่มือใหม่ (ชื่อซ้ำถูกปฏิเสธ) และเพิ่มผังเข้าฐานทันที
